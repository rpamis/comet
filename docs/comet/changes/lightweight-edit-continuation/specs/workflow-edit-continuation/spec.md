# 工作流日常编辑与轻量续行

## 范围与兼容

本能力覆盖 Native、Classic 的日常文档/代码编辑与正常 Git 操作后的续行，包括当前 SDK 和仍受支持的 Compat 入口。两个工作流保留独立状态机，复用稳定的变化记录契约。

升级保留 active change 的 Run、用户文件、有效决定和执行记录，不默认回 Shape 或全量重验。缺少必要证据时只处理具体缺项，不能声称已证明有效。显式严格策略与检查输入保持用户选择，不静默改配置，不重写归档历史。

## 变化记录与判断

Runtime 记录文件新增、删除、内容变化及对应版本，提供原始差异，不通过用户代码语言解析、AST、注释识别、编译命令或语言支持表判断语义。自身状态文件与协议解析仅承担存储职责。

当前 Agent 根据需求、差异、上下文和既有结果，判断哪些决定及检查仍然适用、需要补什么。Runtime 记录判断对应的输入与真实执行结果，在已有授权下推进，不再用编译证明判断。连续编辑在下一次推进合并处理，不为保存、状态查询或同字节重写另建审查会话。判断后又发生变化时只补处理未覆盖差异。

## 决定与证据

需求批准、候选接受、各项验收、检查与报告分别按影响处理。无关变化不清空整组结果；原检查保留真实输入和执行身份。新失败、中断、超时和未执行不能用旧成功或 Agent 摘要改成通过。

已有授权覆盖的工作直接继续。实质范围、验收或授权变化且现有决定未覆盖时，说明差异，只请求相应决定，保留其余有效工作。Agent 不确定时调查或补必要验证，仅在缺少业务决定、授权或外部信息时提问。

## 日常推进与恢复

正式说明、格式及普通文档编辑由当前 Agent 判断实际影响。Native Build 不以 Verify 候选存在作为判断前提；Classic 已批准 Design、Build、Verify 和待归档同样在原 Run 继续。

保留原有必要的 Builder/Verifier 分工，普通编辑不额外新增独立审查。恢复时保留工作并核对未知结果，不重放完成的提交、归档或交付。真实状态缺失与普通编辑分别诊断，不覆盖用户文件或机械重建 change。

## Git 与交付

文件内容、暂存状态、提交历史与交付身份分别表达。相同内容的暂存、取消暂存或空提交，不仅凭元数据废弃实现候选。Agent 决定明确 Git 依赖检查的必要处理；CI、Review 和交付核对实际 SHA，旧提交通过不直接变成新提交通过。

## 性能

同一观察阶段共享输入、路径和适用的 Git 信息，减少重复扫描、项目根与祖先链读取、查询和交付路径线性查找。实际执行前后保持各自的新鲜观察，读取不完整不记为成功，不能以跨用户等待的旧观察掩盖新编辑。

固定机器、fixture、源码/构建身份与采样方式，对比完整推进及编辑续行，记录耗时和操作数。热点重复工作与中位耗时下降，正常路径无可重复回退；不以失败路径或未执行场景冒充提速。

## 发布与验证

中文/英文 Skill、公开 CLI 与生成 Runtime 一致。中文先行并按仓库规则同步英文，通过构建生成资产，不修改安装副本实现产品行为。实际用户行为修复先复现并登记来源、case ID 和精确测试。

契约、生成 CLI、安装、真实 Hook、真实模型 Eval 与性能分别报告；只有安装/Hook 相关边界变化时补对应验证，不默认全量测试。Agent 语义判断必须有真实模型 Eval，确定性测试不能替代。开工核对 master，全部最终用户可见变化统一为后续一个版本；英文 Changelog 不记录开发流水账。

### Scenario: 语言无关

验收：A1

多语言混合、未知扩展名、纯文档、无项目编译器的编辑均返回完整变化并交当前 Agent 判断，不因语言条件阻塞，实际项目验证另行选择。

### Scenario: 正式文档续行

验收：A2

Classic 已批准设计追加空行或 Native Build brief 补说明，Agent 判断契约未变后原阶段、原 Run 继续，无需重新批准、需求修订或额外审查。

### Scenario: 文档证据更新

验收：A3

Verify 或已批准待归档编辑普通说明，无关检查执行零次，有效验收和批准保留；确实影响文档检查时仅补相关检查，交付包含用户编辑。

### Scenario: 实现影响

验收：A4

模块 A 改变而 B 无影响，只补 A 的必要检查，B 有效结果保留；注释改变实际行为时按 Agent 的影响判断处理。

### Scenario: 用户决定

验收：A5

目标、验收或方案变化且授权未覆盖时，仅请求相关决定；未获决定不推进受影响工作，其他成果保留。

### Scenario: 合并编辑

验收：A6

十次保存后一次推进合并变化；重复查询和同字节重写不重复审查。无关编辑新增确认、未受影响检查执行、额外独立审查 Agent 均为零。

### Scenario: 判断新鲜度

验收：A7

Agent 查看后新增编辑，旧判断不覆盖新内容；当前 Agent 补处理新差异，保留原有效工作，不重开流程。

### Scenario: 真实检查结果

验收：A8

既有成功后出现失败、中断、超时或未执行，不能用旧成功或摘要改成通过；其他有效结果仍可适用。

### Scenario: Git 状态

验收：A9

暂存、取消暂存或空提交不机械作废相同实现；明确 Git 依赖正常处理，交付、CI、Review 仍核对实际提交。

### Scenario: 中断恢复

验收：A10

继续同一 Run，保留文件、有效决定和完成工作；已完成副作用不重放，结果未知先核对。

### Scenario: 结构损坏

验收：A11

普通编辑续行；真实缺失、路径替换或读取不完整定位具体问题，不伪造完整输入或覆盖用户成果。

### Scenario: 性能对照

验收：A12

同机、同 fixture 和采样比较完整推进、编辑续行、大目录和多 Action，记录耗时与各类操作数；热点重复工作和中位耗时下降，正常路径无可重复回退。

### Scenario: 发布一致性

验收：A13

中英文 Skill、公开 CLI、生成资产一致；旧 active change、显式配置和历史按兼容约定保留。分别报告适用的各层验证，按 master 统一版本和发布说明。
