# Comet 插件运行时

> 本文是 `comet-plugin-runtime` child 的实现规格。Supervisor Change 中关于个人记忆、项目规则、Skill/CLI 和 Dashboard 用户体验的完整验收，分别由依赖 child 和最终集成 Verify 完成。

## 目的

Comet 提供公开、稳定的插件运行时，让第一方和第三方能力通过同一套接口接入。运行时只负责生命周期、路由、隔离、持久化和诊断，不把任何第一方领域模型塞进 Core。

## 公开接口

- 第一方和第三方插件使用同一套公开接口完成发现结果登记、加载、生命周期、配置、诊断和能力调用。
- 插件通过公开接口接收带来源的 workflow 事件、受控上下文请求、用户/项目作用域信息、只读配置和插件级隔离存储。
- 插件可以声明事件订阅，提供上下文贡献、能力调用和 Dashboard 页面贡献；运行时捕获每个调用边界的异常。
- 插件拥有独立名称、版本与兼容范围；不兼容插件在加载和主动启用前被拒绝并产生可理解诊断。
- 插件不能访问另一个插件的私有配置、存储、日志或运行时内部状态，也不能修改 Native、Classic、Hotfix 或 Tweak 的状态机与 Guard。

## 生命周期与作用域

- 第一方插件在运行时协调时自动登记为启用；用户显式停用或卸载后，后续协调和版本更新保留该选择。
- 第三方插件安装和更新必须由用户动作触发，系统来源不得静默执行。
- 停用停止事件、上下文、能力和页面调用但保留状态与数据；卸载移除运行入口但不自动删除数据。
- 插件可以声明 `user` 或 `project` 作用域；项目作用域调用带有 `projectId`，用户可以只暂停或恢复一个项目。
- 更新完成后，旧的活动实例必须销毁；下一次调用加载新版本实例。

## 隔离与诊断

- 每个插件获得以插件标识、作用域和项目标识隔离的存储句柄；Core 不把共享状态句柄交给插件。
- 插件配置通过只读副本提供，配置更新只影响目标插件并使其后续实例读取新配置。
- 缺失、不兼容、启动、事件、上下文、能力或 Dashboard 贡献失败均返回统一诊断；健康插件继续运行。
- 运行时诊断不伪装成项目编译、linter、测试或 workflow 失败。

## 验收示例

- 一个最小第三方插件可以完成安装、启用、接收带来源事件、调用公开能力、停用和卸载。
- 第一方协调自动启用两个描述符；用户卸载其中一个后再次协调不会装回，另一个仍可运行。
- 一个项目插件只在启用的项目作用域接收事件；暂停项目 A 不影响项目 B 或用户级插件。
- 一个插件的上下文、能力或 Dashboard 贡献抛错时，其他插件仍可返回结果，并在诊断中标明插件和阶段。
- JSON 状态适配器恢复启用、停用和卸载状态；不兼容插件不会被加载。

## 非目标

- 不在本 child 实现个人记忆学习、同步、检索或管理。
- 不在本 child 实现项目规则发现、候选交互、上下文策略和 `comet rules` 命令。
- 不在本 child 实现 Dashboard 主侧边栏、中心页或宿主 workflow 页面。
- 不根据项目内容自动下载、安装或执行第三方代码。
- 不在本 child 固定包格式、进程模型或线协议。
