# Native 流程效率优化

## 目标

优化 Comet Native 的 Build、Verify、恢复和 Archive 执行路径，减少重复审查、无效检查、协议填写错误和无关脏文件造成的等待，同时保持验收独立性、候选绑定、工作区保护和 Supervisor 集成边界。

本 change 执行已确认的十项优化计划：取消普通 change 与 Supervisor 父级的强制前置复核；让检查失败在同一候选内恢复；登记检查前完成平台预检；生成当前状态绑定的输入模板并支持无副作用校验；让 Dashboard 浏览器测试使用当前构建；避免 brief 与 Spec 重复生成验收；让修复后的正式 Verifier 一次覆盖完整候选；复用同候选同机器的有效检查结果；允许 current/keep 归档保留范围外修改；保持 Verifier 独立判断并让所有结论可追溯。

## 已确认的决策

- 普通 change 和 Supervisor 父级不再强制提交前置只读 review；正式独立 Verifier 仍必须判断实现和完整验收范围。
- Supervisor Child 验收、集成检查、父级最终验收、`runId` 与工作区身份检查继续保留。
- 检查结果只在同一候选、同一机器、同一工作区且输入未变化时复用；不实现跨候选缓存。
- 环境故障与代码失败分开处理；可重复检查在当前候选内恢复，非可重复检查保持阻塞或等待明确处理。
- 不新增调度器，不合并 Native 与 Classic 状态机，不把手填结果当成 Runtime 证据。
- 不使用 Superpowers Skill；实现只依赖 Comet Native Runtime、仓库自身 Skill 和平台能力。

## 性能边界

- 未改变的成功检查不得因普通状态恢复、验证结果提交或 current/keep 归档重复执行。
- 计划输入在登记前完成一次完整预检；无效计划不得占用执行状态或增加失败计数。
- 修复后默认只启动一次覆盖完整候选的独立 Verifier；局部修复重点作为提示，不另生成一轮局部验收。
- 任何复用都必须绑定候选、工作区、命令、规格、实现输入和工具环境；无法证明输入稳定时重新执行。
- 归档只提交 change 拥有的路径，范围外修改及其暂存状态必须保留。

## 非目标

- 不改变 Native 用户可见的 Shape 确认、需求修订、Archive 确认和 Supervisor 子任务语义。
- 不承诺固定百分比的耗时下降；通过执行次数、重试次数、重复审查次数和总耗时记录实际效果。
- 不修改 Dashboard 产品功能；Dashboard 仅作为浏览器验证入口的新鲜度测试对象。

## 约束与验证

- Native Runtime 源码位于 `domains/comet-native/`，平台进程策略位于 `platform/process/`，发布 Skill 先中文后英文同步。
- 每项变更先补失败测试，再补最小实现；完整流程最终在临时项目、真实进程和真实工作区中验证。
- 归档时只显式暂存本 change 的文件；不修改 `website` 子模块和主工作区已有无关修改。
