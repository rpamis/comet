# Outcome

提供个人记忆插件的领域服务，让 Comet 在不保存完整对话、trajectory、原始 diff 或完整命令输出的前提下，沉淀可读的全局画像和项目记忆，并在后续任务中按需使用。

# Scope

- 以公开领域 API 管理全局 `profile.md` 和项目 `projects/<project-key>.md`；文件只展示当前生效内容，来源、候选、历史和索引放在记忆仓库的 Runtime 数据中。
- 支持显式记住、纠正、删除和回滚；用户直接新增、修改或移除 Markdown 内容时，下一次读取以用户编辑为准，并保留可回滚历史。
- 接收带来源的轻量观察，在稳定成功检查点形成候选；同一项目身份、workflow 家族和 change ID 只计一次，至少两个独立且成功的 change 提供一致无冲突证据后自动生效。
- 提供按全局/项目、任务、路径和操作过滤的结构化检索与固定上限上下文结果；显式记忆、项目匹配和更具体结构化匹配优先。
- 通过抽象 Git 同步接口同步专用私有记忆仓库；本地无 remote 时仍可用，远端失败保留本地数据并返回可重试状态。
- 由宿主提供同一仓库的规范化身份并通过稳定 project key 识别 worktree、目录移动和重新克隆；不同 fork 使用不同身份。
- 使用文件锁与原子写入保护跨进程更新，合并不同内容、去重等价内容，不静默覆盖用户手动编辑或并发冲突。
- 导出个人记忆第一方插件描述符，使用 `comet-plugin` 的公开生命周期、事件、上下文、作用域、配置和存储接口；不实现 CLI、Skill、Dashboard host wiring。

# Non-goals

- 不实现 Dashboard 页面、CLI 命令、Skill 文本、Hook 或宿主接线。
- 不实现项目规则、linter、构建插件、Agent 指令或团队共享规则。
- 不新增 Comet 账户、登录、远端中继或独立同步服务；Git 凭据由宿主提供。
- 不把个人记忆写入当前开发项目仓库，不创建项目内的可写镜像。
- 不保存完整对话、工具调用、原始 diff、完整命令输出或新的 trajectory 文件。

# Acceptance examples

- 用户显式记住“只暂存本次改动文件”后，个人记忆立即可检索，并保留来源类型与作用域。
- 用户手动创建 `profile.md` 的沟通偏好列表后，下一次读取立即使用新增内容；Comet 更新时保留已有文字、注释和顺序。
- 用户在项目记忆中把 `pnpm build` 改为 `npm run build` 后，只有该项目的相关构建检索结果改变，其他项目不受影响。
- 未形成记忆的新项目不会创建空的 `projects/<project-key>.md`；用户手动创建后可立即读取。
- 第一个成功 change 的重复暂存行为只形成内部候选；第二个独立成功 change 一致观察后自动生效，不要求逐条确认。
- 同一 Hotfix 或 Tweak change 在恢复会话、跨聊天或原地升级时只计一次观察；失败或取消 change 不能满足自动生效条件。
- 当前请求与历史记忆冲突时，检索结果标记旧记忆被忽略，当前请求优先，且不会自动执行未授权的推送、删除或发布。
- 关闭自动学习后显式记住仍然生效；关闭检索后已有数据保留但不产生上下文结果；项目 A 暂停学习不影响项目 B。
- 同一仓库的 worktree 和重新克隆使用同一项目 key；不同 fork 使用不同项目 key，默认不加载原项目记忆。
- 两个并发写入增加不同记忆时都保留；等价内容只出现一次；并发手动删除后，旧观察不会静默写回。
- 专用记忆仓库只包含 `profile.md`、`projects/` 和必要 Runtime 数据；同步失败不影响当前任务，后续可以重试。
- 个人记忆插件通过公开插件接口独立加载、停用和卸载；插件不可用或失败时不影响项目规则插件与基础 workflow。

# Constraints and invariants

- 记忆作用域只有全局个人和项目；项目事实、命令与路径习惯默认不跨项目。
- 当前用户要求和仓库现状高于历史记忆；服务不把记忆当作外部操作授权。
- Markdown 文件是用户可读的唯一当前内容来源；内部状态不得要求用户维护机器字段。
- 常驻画像和按需结果都有固定保守上限，检索不依赖 embedding 或向量数据库。
- 自动整理和同步失败必须保留原数据；写入必须原子化并可恢复。

# Decisions

- 使用“小型画像 + 按需详情”两层结构。
- 用“项目身份 + workflow 家族 + change ID”作为观察去重键，Hotfix/Tweak 仍以 change 为单位。
- 自动学习候选在两个独立成功 change 一致后自动生效，不要求用户接管；显式记忆始终立即生效。
- 记忆文件采用普通 Markdown；来源、历史、候选和索引放在专用仓库 Runtime 元数据中。

# Open questions

- 具体上下文条数和字节上限留给后续 Design/Eval 校准；本 child 使用可配置的保守默认值。

# Verification expectations

- 领域测试覆盖显式管理、Markdown 同步、去重与自动学习、作用域检索、并发/原子写入、Git 同步失败隔离和插件描述符。
- 运行个人记忆测试、TypeScript 检查、架构检查和受影响文件的 Prettier 检查；不要求 Dashboard、CLI 或宿主 E2E。
