# 全流程 CLI 性能与行为兼容

澄清状态：用户已选择 Q3：A、Q4：A、Q5：A，本稿已同步这些决定，待完整 Shape 确认。确认后先建立基线；在用户进一步确认最低收益目标前，不开始性能优化实现。

## 能力与适用范围

Comet 在保持既有 CLI、Skill、Classic/Native 状态机及安全约束的条件下，降低流程推进中的自身执行成本。本能力包括完整命令覆盖记录、可复现测量、依据测量实施的重复工作消除，以及行为与性能回归验证。只完成测量工具、只优化 status 或仅给出设计不构成目标完成。

按 Q3：A，允许保留每次 CLI 启动 Node，不要求本轮消除全部冷启动；完成目标是 Classic/Native 代表性链路自身等待的实测改善，仍须满足 Q4：A 的最低收益目标。公开调用方式和现有进程边界保持不变。

本规格补充而不替代已发布的 [CLI 效率](../../../../specs/workflow-cli-efficiency/spec.md)、[Node Runtime 性能](../../../../specs/node-runtime-performance/spec.md)和[工作流可靠性](../../../../specs/workflow-reliability/spec.md)契约。验收项统一列在本 change 的 brief；下列章节给出这些验收项对应的完整行为。

## 一、完整命令覆盖

覆盖清单必须同时来自公开 CLI 注册、Classic 各阶段 Skill、Native continuation、共享入口/包装器及独立 bundle。每项包含命令族及实际分支、调用来源、阶段、频率或已观察次数、读写副作用、实现入口、场景、测量与行为回归结果。没有采集到频率时记录 unknown，不编造调用权重。

必须登记以下范围：

- 共享 `workflow resolve --activate`、`status`、`resume-probe`，项目定位、工作流选择及恢复。
- `task` 首次/阶段变化/展开上下文/反馈/完成；实际流程调用的 memory/knowledge，并区分配置开启和关闭。
- Classic intent、workspace、OpenSpec 包装与 state 初始化/选择/发现；full/hotfix/tweak 流程。
- Classic state check/next/get/set/artifacts/scale、complete-design、handoff、guard、transition；任务 ID/完成/计划同步/checkpoint/rebind/恢复。
- Classic check 首次执行、成功复用、失效、失败重试；archive 预检/执行、delivery 记录/验证及交付中断恢复。
- Native new 的 current/branch/worktree、select、status 列表/指定/详情/分页及 show。
- Native next 的 Shape 准备/确认、Builder handoff、候选冻结与检查计划；spec disassociate/remove/sync。
- Native next 的 Verifier 分派/启动/请求检查/回传/错误/不可用/重试、结果接受、实现/需求修订及解除阻塞。不能用 legacy check 代替当前 next 的验证路径。
- Native Supervisor 子任务调度、检查、回传、重连、取消、集成与跨工作区操作。
- Native doctor/修复、归档预检/执行、keep/merge/push/pull-request 收尾，以及事务和 finish journal 恢复。
- Hook 的 context/non-write/write/unknown 输入；无选择、多 change、跨工作区、项目外路径、allow_paths、正式产物与拒绝后的恢复。
- 低频兼容路径：Classic validate/root show/move，Native init/root show/move、legacy check 和迁移。

全部核心命令和关键故障/恢复路径必须有可重放隔离场景，或明确说明等价覆盖依赖的相同实现与契约。不适用需要逐项理由，不能用“低频”排除。未覆盖必要场景时保持未完成，不以环境缺失作为通过。

外部 OpenSpec、Git、测试及网络操作登记调用关系并单列耗时；不改变其进程/副作用语义。Dashboard、Eval 产品、Bundle、Creator 等独立功能不在本次改造范围。按 Q5：A，Windows 完整前后性能对照和三平台受影响兼容验证属于必需证据；macOS/Linux 性能对照、真实模型全程、未触及的真实远端服务和额外 Agent 宿主可作为补充证据。补充证据未运行不冒称通过，也不把它们作为无条件的新增交付前置。

## 二、可信基线与计量

测量采用等价的 0.4.2 基线和候选入口，记录源提交、实际构建/包身份、Node/Git/OS、机器、项目规模、worktree/历史 change 数、配置、样本量、预热、采样顺序和原始结果。基线/候选不能使用不同命令、不同成功条件或不同 fixture 来获得成绩。

区分以下时间：

1. 外层 shell、shim 和 Agent 工具往返。
2. Node/模块加载、CLI 路由、领域执行和输出。
3. Git/worktree 探测、目录发现、状态解析、Hash、锁和持久化等可归属成本。
4. 用户测试/构建、OpenSpec 上游、Git 实际合并/提交/推送、网络服务。
5. Agent/Verifier 模型生成、宿主调度与用户确认等待。

分别测量新 Node 进程、文件缓存预热的新进程、现有 daemon 冷启动/真正热调用/空闲重启/关闭或不可用回退。文件缓存预热不称作常驻进程复用。归档、验证及短写入不能只用只读查询代替。

报告包含单命令与代表性完整阶段链路的 P50、观察到的 P95、绝对耗时、变化比例、实际 Node/子进程和 Git 次数、文件工作量的采集边界；daemon 场景继承既有队列/内存指标。无法采集的指标为 unknown/null，不补零。OS 文件 I/O 计数不等于全部文件 API 调用。

Git 计量覆盖共享适配器之外的直接子进程调用，清楚区分 CLI 客户端、daemon 和外部进程。仪表开销单独评估，默认 stdout/JSON 不混入诊断；不得持久化凭据、敏感环境变量或用户文件正文。并行耗时不能简单相加成用户墙钟等待。

样本必须校验 spawn/退出码和实际后置状态/continuation；失败、超时、走错动作或 fixture 不合法不计为成功样本。隔离 HOME/cwd、fixture 建立、快照恢复与清理均在计时外，每个写样本从等价合法状态开始；绝不在真实用户项目反复归档、推送或制造故障。

## 三、可证实的优化结果

按实测累计成本和调用频率选择热点，优先消除重复 Git/worktree 观察、状态读取解析、扫描和摘要工作，结合现有上下文机制及基准脚本扩展。不能把已经在 0.4.2 中完成的优化重新算作本次新增收益。

按 Q4：A，先建立测量场景和必要计量，收集基线与热点证据；这一阶段不改变生产行为，不提前实施去重、缓存或 Skill 调用优化。取得基线后，向用户提交 Classic/Native 各自代表性链路的可达收益、最低目标、绝对减少的毫秒/秒数、噪声区间与回归容差，等待明确确认。

最低收益目标获准后写入正式 brief/Spec，按 Native 重新确认相应需求，再开始性能优化实现。采样规则和判据在实现前固定；候选结果出来后不能反向放宽。规则确需修正时说明原因并重新采集完整可比证据；用户不接受目标时保留基线与未改的产品行为，不擅自转入优化。

Classic/Native 的代表性链路必须分别达到用户确认的最低收益；不能仅凭任意小幅超噪声改善判定完成。热点同时具有减少工作的确定性证据和超出固定噪声区间的耗时收益。其余覆盖场景不得超过固定回归容差；必要例外单列用户影响并取得接受，否则不得判定通过。没有显著收益的代码改动撤回，或另行说明保留理由，不能虚报加速。安全边界内未达到目标时如实报告未完成，不以基准工具交付替代原目标。

继续保持既有特定 fixture 的确定性预算：task 身份查询有 origin 最多一次 Git、无 origin 最多两次；既定 1/10/30 worktree named status 场景最多五次；既定有效 Shape prepare 场景最多七次；已配置且无上下文请求的 workflow resolve --activate 为零 Git。这些不是所有操作的通用上限。

## 四、行为兼容与恢复

相同合法输入下，基线与候选的公开参数、默认输出、JSON 结构、退出码/错误类别、状态转换、文件副作用及后续动作语义必须等价；时间戳等非确定字段按既有契约归一化比较，不能忽略影响授权或内容身份的字段。

Classic 与 Native 继续使用各自状态机。授权、候选/输入指纹、磁盘锁、事务、状态版本、工作区绑定、独立验收、归档及交付恢复不被删除或弱化。失败保留现场并提供正确恢复路径，不增加无进展重试或写请求盲重放。

命名发现仍要检测同名冲突、创建身份、归档继承和必要 Git 祖先关系；不能遇到首个匹配就省略冲突判断。dirty 内容二次修改、切分支、提交后 clean 均按内容身份复验，不能仅依据 Git 状态字符串复用旧成功。

## 五、观察复用有效期

优先复用已存在的命令/操作上下文；复用项须绑定项目根、调用目录、工作区、实际输入/内容身份和语义。只在依赖未变化的受控作用域内有效，不引入新的跨请求状态、授权或验证结果缓存。

状态/文件写入、Git 操作、外部子进程或并发变化可能使观察失效，后续使用必须重新核对相应依赖。需要最新状态的锁内、写前与最终提交校验仍重新观察；不规定“整个命令只能读取一次”，不把减少调用次数凌驾于正确性。

不同请求、项目、worktree 和并发调用之间不会串用上下文、锁、事务、缓存或证据。进程退出后继续使用既有磁盘真相恢复，不引入仅存在于内存的流程状态。

## 六、Skill 调用与安全推进

当前 Runtime 响应已提供足够状态、所有权和 continuation 时，Skill 使用这些结果继续，不追加无用途的 status/show/逐字段查询。现有规则已经做到的部分保留，不为完成任务强行改写。

新会话、上下文压缩后缺失状态、项目/分支/change 切换、外部变化迹象及状态/所有权拒绝时，仍取得必要的新状态；不能通过减少调用省略授权、校验或恢复。必要正文和验收文字按需读取并完整消费相关分页，不能用第一页代替完整 scope。

Skill 内容若发生修改，修改产品源码资产；先完成中文并取得确认，再同步英文。两种语言的触发、输入、失败处理和完成条件等价，不改本地安装副本或上游第三方 Skill。

## 七、daemon、Hook 与外部工作

现有只读 daemon 的覆盖、隔离、构建身份、启动握手、空闲退出、显式停止、有限失败回退保持兼容。写入、确认和验证分派继续走单进程路径；本次不扩大 daemon 写操作覆盖，也不实现 MCP/RPC 或原生语言入口。

Hook 保持独立、有界且失败关闭，正常输入不增加逐请求子 Node 进程。慢扫描/检查失败不能阻塞下一次 Hook；可选插件/上下文失败不能改变 Guard 已作出的合法许可决定。不能把故障情况下的快速拒绝作为正常路径性能改善。

外部测试/构建与远端程序保持既有超时、取消、退出码、证据绑定和恢复语义。使用本地临时远端或受控替身验证包装边界时，报告其与真实远端的差异；测量不得触发真实发布或对外写入。

## 八、报告与验证层级

按 Q5：A，Windows 必须提供完整基线/候选性能实测，Windows/macOS/Linux 均须完成受影响路径的兼容验证。可复用与当前候选和检查范围匹配的 CI 证据；仅有三平台 CI 配置不能证明候选通过。缺失必要兼容结果时保持未完成，不能用 Windows 通过或“其他平台未测”替代。macOS/Linux 性能实测属于补充证据，缺失时不宣称这些平台有具体加速收益。

最终报告逐类列出基线/候选数据、采样规则、实际减少的重复工作、单命令及完整链路减少的毫秒/秒数、未改善项、性能例外、行为回归结果和未验证项。明确这次消除的是重复工作成本，仍有 Node 冷启动及外部耗时。

脚本重放只能证明对应 CLI 链路结果，不能声称真实 Agent 总时长、Token 或模型纠正率得到相同比例改善。全流程覆盖不代表每条命令都变快；未完成必要验收不能把 change 标为完成。

默认执行风险匹配的最小相关测试，不跑全仓测试。涉及 Runtime 源码时同步对应生成资产并验证一致性；单元/集成、生成 Runtime、打包入口、真实宿主 Hook、真实模型和跨平台结果分别报告。未运行的补充项明确原因，不互相替代；涉及已修改边界的必要检查失败、超时或缺失仍保持未完成。

最终由 Native Runtime 接受检查记录和独立 Verifier 结论，按用户授权完成后续流程。当前 change 在用户提供的 `043` 分支、目标 `master`；Shape 确认不等于授权 merge、push、PR、发布或工作区清理。
