# Native 可靠性契约

## Supervisor 子任务

父 change 保存确认的验收范围，子任务任务包携带验收 ID、来源和版本，以及子任务与父级最终验收的边界。Builder、Verifier、候选与 runId 继续绑定。Verifier 对每个范围项恰好给出一次 passed、failed 或 blocked；总判定与逐项结果一致，pass 必须有 Runtime 实际执行通过的正式检查。普通调查说明不算正式检查。

正式检查复用 Runtime 检查执行器，保存退出结果、日志和执行状态；结果与受测候选绑定并按内容寻址读取。外部材料只通过登记引用参与正式验证，消费时核对内容哈希、候选和执行身份。重跑保留历史内容，宿主对普通工作文件的写权限隔离不由 Runtime 冒充。

## 跨工作区状态

状态发现同时考虑活跃和归档记录。已完成记录只有在稳定创建身份、工作区和可达 Git 历史证明它继承旧副本时才替代旧副本。不能仅凭名称或状态版本判断。没有足够关系证据的候选显式报告冲突；最终归档状态和验收计数从归档记录读取。

## 规格与验证恢复

项目正式规格保持由 Archive 发布，Agent 在当前 change 中受控修订完整目标规格。规格同步入口只接受不改变需求与验收语义的交叉引用修正，并记录操作者、原因、修改前后内容和受影响验收项；需求语义变化继续使用 Shape 确认。同步不能修改 Runtime 控制状态、历史归档证据或绕过重新验收。

局部修复保留未受影响结论，受影响场景重新验收，最终仍独立验证完整范围。Verifier 中断按既有恢复状态转换处理，提供明确后续动作。未知协议或状态 schema 在写入前拒绝并提供可操作诊断。

## 发布与交付

发布源码、生成 Runtime 和双语说明保持一致，版本为 0.4.0-rc.6；PR 使用仓库完整模板及 fix 标题，关联三个 issue。交付只在最终 head 的线上 CI 全部成功后报告完成，实际未执行的外部平台验证必须明确说明。
