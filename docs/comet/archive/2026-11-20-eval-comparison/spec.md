# 工作流观察与验收体验

## Classic 上下文成本

Classic 用户和维护者可通过现有交付路径查询指定 change 的上下文成本。报告按常驻 Rule、当前阶段交付的 Skill 和引用、CLI 响应归因。静态计量注明估算口径，平台追踪带实际观测标记，缺失时明确指出缺少的来源。普通聊天路由保持既有行为。验收：A1。

相同工作区、相同源材料、相同阶段范围内省去已交付且仍有效的重复内容。材料变化或恢复需要重新读取时提供完整上下文。用一个完整 Classic 样例对比减少的交付量及可观测的工具往返。审批、独立验收和旧 change 恢复条件继续生效。若调整双语流程文本，已发布中文和英文表达相同操作契约。验收：A2。

## Native 验收证据

Build 交接、独立 Verify 和冷恢复应能读取同一权威 Run 中每个已确认验收 ID 对应的当前候选证据与缺口。验收证据引用候选上可识别的产物、检查结果或明确缺失原因。对于 Supervisor 子任务，证据保留子 Run 和源工作树身份，跨候选或跨工作流的结果不可计入。验收：A3。

Verifier 在已有报告结构中可说明补充、重跑的具体原因。旧 Run 缺少逐项关联时仍可读取并标出缺口，失败、未知、未执行及超时不得记作成功。Verifier 对当前候选的全部验收项独立给出结论。验收：A4。

## Eval 回归对比

通过现有公开 Eval 入口加载固定小套件，标明中断恢复、独立验收、范围变更后二次确认的稳定用例 ID 和适用工作流。通过现有基线、报告和复用机制保持候选配对可追溯。确定性夹具可用于验证用例装配和比较逻辑，模型运行仍使用既有授权机制。验收：A5。

报告逐用例展示前后结果，以及已采集的工具往返、等待时间和上下文成本。工具事件、时间和用量字段保持原始来源和单位，缺失数据标明不可用。无法可靠配对或口径不同的数据不得参与差值计算，报告应提供原因。验收：A6。

## Dashboard 待关注

Dashboard 展示当前项目正在进行的 Native 和 Classic change 需要处理的状态。分类区分等待用户、可执行、结论未知和验收受阻。归属与筛选沿用既有项目和工作树身份，兼容旧数据及多个工作树中的同名 change，已完成归档且无待处理事项的条目不进待关注列表。验收：A7。

点击条目可打开身份匹配的原始 change、Supervisor 子变更或证据详情。在权威状态明确时展示等待依赖、派发位置或集成原因，缺失说明时显示未知。使用既有路由和读取能力，批准及恢复继续使用工作流既有动作。验收：A8。

## 集成验收

同一候选中的 Eval 复用 Classic 计量字段，Dashboard 复用 Native 验收证据。父变更验证两条接入、正常和缺失数据的呈现、浏览器操作和生成物一致性，保留实际验证结果后完成归档。验收：A9。
