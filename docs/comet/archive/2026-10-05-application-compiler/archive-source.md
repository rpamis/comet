# Outcome

重建 comet-any，使用户组合的 Skill 通过共享 Runtime SDK 获得明确的执行、确认、验收、修复和恢复能力。支持 Native 新增流程、Classic Skill 编排和独立工作流；Native 不建设内部组件替换机制。

## Directory structure

### Created

### Modified

预计涉及 Native、Classic 应用装配，CLI 与 Entry 路由，组合和生成逻辑，平台安装适配，产品 Skill 源码及对应构建、测试、文档。SDK 只在真实应用证明现有机制不足时扩展。

新生成链完成验收后替换旧生成脚本与不再需要的创作逻辑；具体旧生成链兼容与迁移已排除，不提前删除用户产物。

### Not created

# Non-goals

# Acceptance examples

- 三种起点均能形成可运行的 Application 包；入口 Skill 能启动并继续对应流程，展示实际验证范围。
- 从入口、CLI 和恢复入口访问同一 Run；修改说明文件或投影视图不能绕过已声明的执行规则。
- 定制应用经公开入口启动、查询和继续均路由正确；同名不同项目或 worktree 不会串用 Run。
- 修改同版本定义、依赖 Skill 或资源后，活动 Run 拒绝按新内容继续；恢复原依赖后可以沿原记录恢复。
- 未满足依赖的越序回报、旧 attempt、错误 Action 归属和陈旧提案不能推进；合法并行 Action 可按任意完成顺序回报；断连后保留原 Action，已发生的外部操作不被自动重发。
- Native 样板增加候选审查后，未通过审查不能进入后续验收；未配置扩展的 Native 不新增外部 Skill 依赖。
- Builder 获得指定版本的指导和范围；产物违反可检查的指导要求时，即使已经加载 Skill 也不能通过对应验收。
- 审查失败可回 Build 修复；新候选重做已失效的检查；额外审查通过不能直接跳过 Native 独立验收或取得交付授权。
- 扩展引入需求变化会返回 Shape 重新确认；未改变确认范围的实现修复沿修复流程继续。
- 普通 Native、Supervisor 父级、Child 和集成验收中的扩展均有效；跨会话继续仍保留要求，父级加载一次 Skill 不能代替 Child 的执行与验收。
- 定制 Classic 在各受影响 profile 中可完成真实流程；无效替换或顺序变化被解释并拒绝，不用文本成功声明替代领域验收。
- Classic 新增或替换的工作发生失败、工件变化和中断时可恢复；基础命令不能绕过组合应用新增的必需检查。
- 独立报告流程在审批前不发布，拒绝或修改后走声明路径，跨进程继续同一 Run；不宣称自动继承 Native 独立验收语义。
- 真实内容不支持所要求能力、依赖缺失或输入输出不匹配时不能生成虚假可运行承诺；第三方原文件不被改写。
- 含有自行发布或接管审批逻辑的 Skill 不能作为普通指导绕过父流程；加载、自报完成、机器检查和独立评审能被区分。
- 相同方案与依赖生成一致的有效产物；未声明转换、缺失验证器及重复或冲突身份在执行前被发现。
- 非法 JSON、缺失必填数据、过期工件、错误候选和伪造完成字符串无法满足相应检查；拒绝后保留现场并给出修正动作。
- 在方案确认或编译验证期间中断后能继续同一次创作；方案变化使受影响的确认和验证失效，不重复执行已明确完成的外部工作。
- 用户能从自然语言需求完成创作；看到实际流程和安装预览；方案或安装目标漂移时原确认不能被复用。
- Claude Code 完成真实 Skill 调用、必要交接和中断恢复；必需能力缺失时明确阻塞，不静默跳过。Codex 适配保留对应的本地契约与回归检查，报告明确未执行其真实宿主和模型验收。
- 外部操作结果丢失后可按适配契约查询或核对，不盲目重复发送或部署；没有核对能力时明确阻塞；产物和持久化记录不包含凭据。
- 真实导出包在项目级与用户级目标安装后均可启动和恢复；同名冲突、升级与有活动 Run 的卸载按明确规则处理；不要求远程分发服务。
- 新产物只走 SDK 应用链，产品不再依赖旧生成和推进逻辑；旧格式被明确拒绝并提示重新生成，不被静默加载或自动转换，用户文件不被自动删除。
- Claude Code 的全部指定流程及恢复场景在当前候选上满足已确认矩阵中的所有规定样本；外部结果核对后操作计数为一；未运行、失败、超时或缺少真实宿主及模型证据时不能完成生产验收。
- 先完成能运行、失败可修复和冷恢复的 Native 样板，再扩展生成能力；基础应用和 SDK 既有契约通过相关回归检查。
- 产品文档与真实行为一致；中英文 Skill 同步后再更新对应发布说明；检查与修改范围可追溯。

# Constraints and invariants

- 本地与远端基线是 be097ae0，当前分支 045；需求文档和 Shape 文件是本轮新增内容，基线推送未包含它们。
- SDK Run 是唯一推进权威；状态、报告、锁和检查结果由 Runtime 管理，Agent 只编辑允许的正式需求文件。
- 当前控制 Runtime 使用本分支构建的 0.4.5，通过进程级临时 PATH 的公开 comet 命令运行；全局安装仍为 0.4.4。临时启动器不属于产品交付物，不提交。
- Shape 未澄清和确认前，不修改产品实现，不启动 Supervisor Builder，不提交接受或推进确认。
- 凭据仅存在执行上下文或隔离环境，不写入需求包、Run、报告或生成配置。

# Decisions

- Q1：产品支持 Codex 与 Claude Code；2026-10-04 的用户补充将本轮真实宿主与模型验收限定为 Claude Code，产品组合能力和流程范围保留。

- Q3：Native 扩展覆盖普通执行、Supervisor 父级、Child 和集成验收全链路。
- Q4：支持本地工作，以及可查询或具备核对适配的外部操作；未知结果先核对，不盲目重试。
- Q5：支持项目级安装、用户级安装和完整包导出。
- Q6：不建设远程分发；按 Q5 提供本地交付。
- Q7：采用分阶段验收，真实宿主与模型仅在 Claude Code 验收。使用 CLI 2.1.251、glm-5.3[1M]，主代理和子代理同模型；六种正式流程各重复 2 次，共 12 个样本，最多并行 1 个，总时限 10 小时。前置 Native 样板独立限时 1 小时；追加预算须取得用户决定，不重置原记录。全部规定样本通过的要求保留。

- 用户已明确采用 Supervisor Change 组织本次实现；父 change 为 comet-any-sdk，工作分支 045。
- Native 只增加流程、指导和验收，不替换其内部组件；Classic 支持 Skill 编排；三种产品起点都在范围内。
- 七个 Child 的拆分和推进 A（多会话协作）沿用用户已确认的选择；本次只调整真实宿主验收范围，保留全部产品能力和依赖关系，最终停留在归档前。
- Child 1: application-foundation。建立组合与 Skill 适配契约、宿主执行器、授权及未知结果核对契约，完成应用加载、版本固定、运行归属和公开入口恢复；以最小可运行应用验证。依赖：无；覆盖：A2、A3、A4、A5、A14、A15。

- Child 3: classic-composition。实现 Classic Skill 编排、业务契约保留、修复与恢复；复用基础应用加载。依赖：native-extensions；覆盖：A11、A12。
- Child 4: standalone-composition。实现独立 SDK 应用与完整报告审批样板，明确分支、join、子流程和修复语义。依赖：native-extensions；覆盖：A13。
