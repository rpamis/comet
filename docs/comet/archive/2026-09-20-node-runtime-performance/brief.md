# 目标

降低 Comet Classic 与 Native CLI 在连续工作流中的 Node.js 冷启动、重复查询和 Hook 固定开销，并提供可按需启用的纯 Node 常驻 Runtime。用户继续使用现有 `comet` 命令；单次 CLI 始终可用，常驻 Runtime 不改变工作流状态机、授权边界或验收独立性。

# 范围

- 在现有公开 CLI 和生成入口中减少重复的身份、状态和确定性动作调用，保持返回的 JSON、退出码和下一步语义兼容。
- 优化 Hook 输入读取和高频只读路径，保留有界输入、超时和失败关闭行为。
- 增加纯 Node daemon：首次只读请求按需启动，通过本地 IPC 处理后续只读请求；按项目、Runtime 构建版本和权限上下文隔离，空闲退出，支持停止、启动锁和单次 CLI 回退。写入、确认和验证派发继续走现有单次 CLI。
- 为常驻 Runtime 抽取可重复调用的只读业务执行接口，Classic 与 Native 继续使用各自状态机和领域模块。
- 为冷启动、热调用、进程次数、Git/文件读取、排队时间和常驻内存建立可复现的本地基准，并覆盖并发、慢任务、进程中断、版本切换和写入响应丢失。

# 非目标

- 不合并 Classic 与 Native 状态机，不删除输入指纹、锁、恢复、快照、独立 Verifier 或授权检查。
- 不使用跨请求授权、验证结果或工作区事实缓存来绕过重新验证；缓存只保存明确不含用户状态的运行时模块和静态结构。
- 不把 shell 常驻当作 Runtime 复用方案，不引入 Rust 或其他原生语言作为本 change 的前置条件。
- 不修改上游 Skill，不修改 `website` 子模块，不启动真实模型 Eval 或远程部署。

# 验收示例

- A1：现有单次 CLI 与常驻 Runtime 对同一合法请求返回一致的 JSON、退出码、状态变更、错误分类和下一步动作；daemon 不可用时单次路径仍可完成。
- A2：第一次请求按需启动一个与项目、构建版本和权限上下文匹配的 Runtime；同一上下文的后续请求复用该进程，空闲退出后能重新启动，停止命令不会留下可继续接收请求的实例。
- A3：两个不同项目或 worktree 的并发只读请求不能共享 cwd、环境、当前 change、授权、锁、缓存或输出；写入请求不进入 daemon，继续由现有 mutation lock 和 state-version 检查保护。
- A4：慢 Git、文件扫描或 Native 检查运行时，Hook 请求仍在有界时间内得到结果；慢任务失败、取消或超时不会阻塞后续 Hook，也不会留下无法恢复的锁。
- A5：daemon 启动竞争、IPC 断开、协议错误、版本不匹配和进程崩溃均返回可解析诊断并回退到单次 CLI；不会无限重试或重复派发写操作。
- A6：写入请求不进入首版 daemon；因此响应丢失仍由现有持久化状态、请求恢复和确认路径处理，客户端不会把 daemon 失败当成“未执行”并重放写入。
- A7：Hook 输入读取不再为正常已关闭输入额外启动 Node 子进程；无输入、超时、超限和非法输入仍在有界时间内失败关闭，并保持平台输出协议。
- A8：首版 daemon 不自动合并或重排命令；现有 Skill 的确定性批处理继续由调用方显式组织，遇到状态变化、权限边界、检查失败或需要确认时仍按原命令边界停止。
- A9：合法成功 fixture 的冷启动、热调用和回退基准记录 Node/OS、构建身份、样本、进程数、Git/文件读取、median/p95 和内存；热调用不得重新创建 Runtime 进程，且报告不把失败快速退出算作收益。
- A10：源码、Classic/Native/Entry 生成 Runtime、打包资产和测试保持一致；现有锁、指纹、恢复、授权、插件失败隔离和独立验收回归全部通过。

# 约束与不变量

- 每个请求必须显式携带项目根、工作目录、Runtime 构建身份和请求 ID；daemon 不依赖共享 `process.cwd()`、`process.argv` 或可变全局环境处理请求。
- IPC endpoint 只能由当前用户访问，并绑定项目根、Runtime 版本和权限上下文；禁止跨用户或跨项目复用。
- daemon 只复用代码和静态结构；涉及工作区、Git、授权、输入、状态版本和验证证据的事实仍按既有有效期重新读取或校验。
- 写操作必须有幂等请求记录或等价的持久化状态核对；客户端超时不能直接推断“未执行”。
- Hook 与长任务使用独立执行容量；单项 Git/文件操作保留现有超时和失败关闭语义。

# 决策

- 采用纯 Node 实现首版 daemon，客户端和 Runtime 共用现有 TypeScript 业务模块；不新增 Rust 构建矩阵。
- 先交付调用减量、Hook 输入读取和可复现基准，再迁移高频只读命令与 Hook，最后根据证据决定是否迁移写命令。
- 常驻生命周期采用按需启动、单实例握手、空闲退出和显式 stop；默认不做永久后台驻留。
- 性能收益以同机合法成功 fixture 的实测对照为准，不预先承诺完整模型任务的固定百分比收益。

# 待解决问题

- 无阻塞的产品范围问题。具体 IPC 序列化格式、endpoint 命名和 daemon 内部模块拆分由实现阶段按现有 CLI 术语确定，并由测试固定。

# 验证预期

- 先运行 Hook、CLI facade、IPC、请求隔离和故障恢复的定向测试，再构建 Classic、Native、Entry 生成物并运行生成一致性检查。
- 运行冷启动与热调用基准，分别记录首次启动、复用、空闲退出重启和单次回退；不把外层 Agent 工具耗时冒充 Runtime 耗时。
- 使用真实临时项目和并发进程验证两个项目/worktree、慢检查、daemon 崩溃、版本切换、写响应丢失和锁恢复。
- 最终交付前按当前改动范围运行格式、lint、build 和相关测试；全仓测试仅在改动跨越高风险发布边界且用户要求时执行。
