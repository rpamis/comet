# Outcome

让 Native、Classic、Hotfix、Tweak 工作流在出现可复用的用户偏好或协作习惯时，可靠提交观察、形成候选、积累独立成功证据并在后续任务中检索使用。没有合格观察时不制造记忆；用户可以查明未学习、跳过、待重试和已学习的真实原因。

本轮已完成 Shape 澄清并进入实现与验收。版本保持 0.4.1；只有通过分层验收的用户可见变化才进入现有 0.4.1 Changelog。

# Scope

## 已核对的问题与证据边界

- 当前源码在隔离目录中可以完成首次候选、同一 change 去重、第二个独立 change 晋级和重新检索。
- HEAD 完整旧源码也能通过同样的观察流程产生 proven 记忆。不得继续将根因描述为“旧 observe 一定被过滤”。
- 当前被语义评审拒绝的任务摘要错误返回 deferred，状态还保留上次 candidate-promoted。
- 当前直接观察遇到评审异常后，虽然提示已延后，重新创建服务并同步仍没有恢复观察。
- 当前没有任何观察也可以记录 submitted。普通完成事件没有偏好证据时不会自行生成记忆。
- 新工作流检查指引尚未进入当前本地安装副本；源码测试不能证明实际 Agent 使用了新版本。
- 真实宿主、真实模型、远程 Provider 的完整学习链路尚未验证；评审 Skill 的首次候选指引需要与 Runtime 统一。

## 实现工作包

1. 观察持久化与恢复：优先复用现有 experience journal / Reflection 队列，通过公开 Bridge 接入。先可靠保存最小合格观察，再执行有界评审；成功后确认处理，失败保留可恢复状态。不得另建常驻 worker。进程中断、重复投递和并发重试不增加独立证据。
2. 结果与计数：区分 skipped、deferred、candidate-created、deduplicated、candidate-promoted 和策略禁用；沿用同义既有命名。跳过和错误也更新本次诊断。仅真正持久化待重试后允许报告 deferred。总观察、有效证据、尝试次数的语义分别定义，重试不能制造成功证据。
3. 完成检查绑定：关联稳定项目身份、workflow、change 和实际观察。submitted 表示可查到本任务提交，不代表评审通过或晋级；无对应观察时报告无法验证。当前任务结果不能由其他项目/change 的旧记录代替；保留无观察、未检查和状态不可用的区别。
4. 首次候选评审：统一中文、英文 comet-memory 及 Native/Classic/Hotfix/Tweak 指引和默认评审。首次合格隐式信号允许形成候选；不同成功 change 的一致无冲突证据才晋级。终止性语义跳过、安全拒绝与暂时执行失败分开处理；不对确定性拒绝无限重试。
5. 诊断展示与远程兼容：CLI、Dashboard 通过同一公开能力读取最近检查时间、任务归属、处理结果和简短原因。Dashboard 不把开关开启当作已学习。远程 Provider 读取权威状态；旧服务不支持新增能力时显示不可用，不伪造成功，不回退到本地记忆。
6. 工作流触发与安装验证：在已选四类工作流的合适成功检查点/任务结束检查可复用信号，提交合格观察。保留当前候选和来源的关联；没有 change 的普通任务不新增自动学习。通过正常构建、打包和安装流程验证发布 Skill、CLI、Hook/无 Hook 路径；不手改 dogfood 副本代替产品修复。
7. 恢复和数据兼容：兼容没有学习诊断的旧状态，不重置已有记忆、候选或删除记录。暂停期间不处理新的学习；恢复时重新检查策略、当前用户修改、冲突和 tombstone，过期观察不能恢复已删除内容。所有新增状态和队列使用现有有界存储规则并保存必要最小证据。
8. 交付：补齐回归、生成资产和安装验证；中文 Skill 先完成语义确认后同步英文。版本仍为 0.4.1，按与已发布版本的用户可见差异决定是否合并更新现有 Changelog，不记录开发过程。

## 代码定位与实施顺序

先处理 domains/comet-memory 与 domains/comet-plugin 的持久化、幂等、评审及状态；再处理 app/commands/personal-memory.ts、app/commands/comet-task.ts 和 domains/comet-entry/plugin-context.ts 的公开接入；随后处理 remote-provider.ts、Dashboard 和 assets 中英文 Skill；最后构建受影响 Runtime 并验证安装产物和真实 Agent。

以上为责任定位，不授权重写无关模块。新增跨领域入口前核对 config/repository-layout.json 和目录规则。具体记录 ID、队列退避和事务组织由实现阶段根据既有契约决定，不另设用户配置。

# Non-goals

- 不覆盖没有 change 的普通 Comet 任务，不新增全局对话抓取或历史任务批量回填。
- 不把任务摘要、代码事实、测试报告写成个人偏好；不扩大 Project Knowledge。
- 不自动把项目观察升级为全局记忆，不更改显式 remember/correct/forget 的授权语义。
- 不引入新后台服务、embedding、向量数据库或长期原始轨迹存储。
- 不改变 Native/Classic 状态机、独立验收或交付确认要求。
- 不修改 website，不清理既有未提交工作；本次 Shape 不提交、不推送、不发布。

# Acceptance examples

- A1: 新存储中首次提交合格偏好形成候选，同一 change 的重复提交和恢复不增加独立成功证据，第二个独立成功 change 才能晋级并被新进程检索。
- A2: 评审异常或超时后观察已持久化且显示待重试；进程退出后恢复同步能处理一次，不丢失、不重复晋级，不能无限阻塞主任务。
- A3: 上次晋级后提交一次性摘要，输出和后续状态都显示本次跳过及原因，不显示延后或沿用上次晋级；确定性拒绝不进入无限重试。
- A4: 零观察、其他 change 或其他项目的观察不能证明当前任务 submitted；已有持久化观察能显示其真实候选、跳过或待评审结果。
- A5: Native、Classic、Hotfix、Tweak 均提交带稳定项目、workflow、change、主题和可信成功证据的合格观察；失败/取消不增加成功证据，同一 change 的路径切换不重复计数。
- A6: 新旧中英文评审契约统一为首次可创建候选、Runtime 决定晋级；没有合格偏好时允许无观察或 skip，不要求每次任务产生记忆。
- A7: CLI 和 Dashboard 对同一任务显示一致的最近检查、结果和原因；从未检查、未检查、无观察、待重试、跳过、已形成候选和已晋级能被正确解释，不暴露内部证据正文。
- A8: 远程服务支持诊断时展示真实结果；不支持、认证失败或超时时显示可读的不可用状态，不伪造开启/成功，不访问本地记忆作为替代。
- A9: 旧存储缺少诊断字段仍可读取已有显式记忆、候选和删除历史，不虚构过去检查；新增诊断、并发和队列恢复不损坏既有数据。
- A10: 待重试时暂停学习或用户纠正/删除记忆，恢复处理尊重最新策略、显式修改和 tombstone，旧观察不能复活删除项或覆盖显式偏好。
- A11: 发布包内 CLI、生成 Runtime 和中英文 Skill 与源码一致；正常安装后支持 Hook 和无 Hook 的工作流都能取得新指引，安装测试不修改用户真实记忆。
- A12: 使用安装产物运行真实 Agent 的受控跨 change 场景：用户提供合格纠正，Agent 自主提交观察；独立成功 change 再次验证后晋级；后续任务实际采用并记录真实 application outcome。无偏好对照任务不产生垃圾记忆。
- A13: 记忆评审、存储或远程故障不改变主工作流原有成功/失败退出结果；错误仍可通过诊断发现。
- A14: 无 change 的普通任务不新增自动观察；自动学习仅写当前项目，显式全局记忆仍正常工作，不混入其他项目或 Project Knowledge。

# Constraints and invariants

- 当前目录 D:/Project/Comet，分支与版本 0.4.1；开始澄清时 HEAD 为 c58e3780acde52482383c93a34605201059f0b3f，保留上一轮未提交实现与 website 既有状态。
- 本地事务、幂等和恢复由 Runtime/领域服务持有；CLI 只编排，Dashboard 只调用公开能力。
- 保持两个独立成功 change 晋级规则；同一 change 的重试、跨会话恢复及 Hotfix/Tweak 升级不算新证据。
- 只存最小偏好摘要和可信来源，不保存完整对话、工具输出、凭据或隐藏推理；已有安全校验不能为了增加学习数量而放宽。
- 用户编辑、显式纠正和删除高于后台学习；远程不可用不得静默回退到本地。
- 层级验证分别报告：源码测试、生成 Runtime、安装包、真实 Hook、真实模型；失败、超时、缺依赖和未执行不视为通过。

# Decisions

- D1（用户已确认）：沿用当前目录和 0.4.1 分支，在既有实现上继续。
- D2（用户已确认）：只覆盖 Native、Classic 和现有 Hotfix/Tweak 工作流，不扩展到无 change 的普通任务。
- D3（沿用正式规格）：项目自动学习、显式记忆立即生效、两次独立成功 change 晋级、主任务失败隔离、暂停与删除优先。
- D4（实现组织）：使用单个 Native change；核心观察/评审/状态链路共享，不拆 Supervisor。
- D5（证据要求）：不能以 observe 人工调用通过代替真实工作流学习验收；保留旧源码对照，避免复用已被推翻的根因。
- D6（范围解释）：不批量回填历史任务；恢复已经可靠保存的待处理观察属于本次故障恢复范围。
