# 目标

让个人记忆、项目知识和 Agent 学习形成一条真实、可验证、可解释的闭环：应该学习的内容能进入有效状态，实际使用后能得到反馈，失效内容不会继续注入；Dashboard 忠实展示当前有效内容、来源和历史，让用户一眼看懂“学到了什么、为什么没学到、任务用了什么”。

# 范围

- 打通显式长期用户信号、稳定协作习惯、项目 Review、失败解决、验证和 Change 归档进入学习循环的生产链路。
- 统一个人记忆与项目知识的形成、去重、版本、失效、反馈和诊断语义，不以“处理过事件”冒充“学到了内容”。
- 统一任务上下文、CLI 查询和 Dashboard 状态使用的项目知识初始化与刷新入口，消除不同入口看到不同状态的问题。
- 使用稳定逻辑身份和内容摘要判断知识是否真正变化；同一知识只保留一个当前版本，旧版本进入历史，不因文件修改时间或切换分支生成近义重复。
- 明确区分有效记录、候选记录、历史记录、索引来源和结论证据；`trial`、`proven`、`enforced` 属于有效生命周期，`superseded` 只属于历史。
- 补齐应用结果反馈：只有实际采用的记忆或知识才回写成功、忽略、覆盖、纠正或导致失败，未使用内容不得自动记为成功。
- 修复个人记忆权威状态、tombstone 和 Markdown 投影不一致；投影文件不得被统计成已学习记录。
- 为现有数据提供可重复的整理与重建路径，清理重复版本并重新生成当前有效项目模型，同时保留必要的历史与遗忘保护。
- 重做个人记忆和项目知识中心的信息表达：使用现有 Dashboard 的紧凑 AntD 语言，提供准确计数、明确空状态、可追溯详情、真实健康状态和可操作的刷新/纠正/废弃入口。
- 将项目知识中的“知识单元”“索引来源”“结论证据”“历史版本”分开展示；来源详情先显示实际关联结论、关系、引用片段和定位，再提供完整文件原文。
- 补充真实端到端验证：执行检索数据集并计算实际结果，覆盖跨任务学习、召回、反馈、晋升、纠正和失效，不再只验证 fixture 数量或硬编码汇总函数。
- 根据与 `master` 和上一个发布版本的实际差异更新 `hotfix0903` 的用户可见 Changelog；仅记录最终可感知变化。

# 非目标

- 不保存完整聊天、隐藏推理、完整 diff、原始工具日志或无边界源码正文。
- 不引入向量数据库、通用知识图谱、Provider marketplace 或 Local/Remote 双写。
- 不让个人记忆覆盖项目策略、当前源码、当前配置、测试结果、系统约束或用户当前请求。
- 不自动修改 AGENTS、Rule、Skill、linter、编译器或 CI 配置来落实项目策略。
- 不重做 Dashboard 的整体导航和视觉系统，不引入独立设计语言。
- 不通过伪造学习记录、默认成功反馈或隐藏历史记录制造“已经学会”的假象。
- 不改动或提交当前工作区中既有的 `website` 子模块变化。

# 验收示例

- A1：用户明确表达长期偏好或要求记住时，该内容通过正常 Comet 入口形成一条 proven 个人记忆并在下一相关任务生效；明确仅限当前任务的要求不持久化。
- A2：一次可信但未明确要求长期保存的稳定协作习惯形成 trial；实际成功使用后晋升 proven，被用户纠正后旧版本立即停止注入且新版本可追溯。
- A3：Review 决策、已闭环的失败解决、成功验证和 Change 归档能在生产链路形成或更新对应的项目策略；语义审查暂不可用时确定性知识继续工作，待处理内容和原因可见且可重试。
- A4：首次进入任务、执行 CLI 查询或打开 Dashboard 时使用同一套项目模型就绪与刷新逻辑，三个入口对有效记录数量和来源新鲜度给出一致结果。
- A5：内容未变化但文件修改时间、检出分支或 worktree 改变时，不新增知识版本；内容真正变化时生成一个当前版本并把旧版本放入历史。
- A6：同一语义身份的知识在有效列表中只出现一次；`trial`、`proven`、`enforced` 可正常浏览，`superseded` 不参与注入并只在历史中出现。
- A7：任务实际采用上下文后记录准确 application outcome；未实际采用的候选保持未反馈，不能被统计为成功或用于晋升。
- A8：当前用户要求、源码、配置或测试与记忆/知识冲突时，当前事实获胜，冲突记录被覆盖、纠正或失效且原因可追溯。
- A9：个人记忆中心分别展示 Core Profile、协作策略、个人经历和历史；记录数只统计权威记录，投影文件、tombstone 和历史项均有独立含义。
- A10：项目知识中心分别展示项目模型、项目策略、索引来源和历史；首屏准确显示有效数、候选数、历史数、最近学习、跳过/延迟原因和反馈覆盖情况。
- A11：来源详情明确显示关联知识的类型、状态、结论、关系、版本和精确引用位置；同一知识的多个历史版本不会伪装成多条无差别的关联结论。
- A12：服务状态、索引诊断、最近查询耗时、候选数量、结果截断和刷新状态来自真实领域快照；错误或数据不完整时不得显示“服务正常”。
- A13：从关联来源跳转到被筛选隐藏的记录时，页面自动切换到可见范围并选中目标；筛选、刷新和页面切换不会造成错误选择或跨项目串数据。
- A14：零记录、未形成学习、等待验证、来源失效和审查延迟分别显示简短、具体的原因和下一步，不用“自动学习已开启”代替实际结果。
- A15：界面沿用现有 Dashboard 的紧凑表格、列表、标签、描述区和抽屉/弹窗，不使用大面积宣传卡片、渐变装饰、拟人化文案、重复总结或模板化 AI 话术。
- A16：迁移或重建现有异常数据后，重复的 superseded 版本被整理，当前有效模型可重新生成；个人记忆的状态、遗忘保护和 Markdown 投影一致，操作可重复执行且不破坏用户纠正。
- A17：自动学习、索引或语义审查失败不阻塞当前工作流；Dashboard 和诊断能说明失败发生在哪一层，显式管理操作失败则保持原状态并返回真实错误。
- A18：真实检索评估会执行 Provider 查询并输出可核对指标，多任务集成验证覆盖“信号 → 形成 → 召回 → 使用结果 → 晋升/纠正/失效”，测试不能只检查数据集存在或使用硬编码结果。

# 约束与不变量

- Record/Provider 状态是知识与记忆的权威机器状态；个人 Markdown 仅作为用户可读投影和可重建输入。
- Personal Memory 与 Project Knowledge 保持独立 Provider、作用域和优先级，不直接复制彼此记录。
- 当前请求、系统约束、当前源码、配置和测试始终高于学习内容；学习内容不授予提交、推送、删除或发布权限。
- 显式长期信号允许确定性写入；语义推断必须保留证据和适用范围，不能从完整聊天或 Agent 自己的计划中臆造长期结论。
- 后台学习和刷新不得阻塞任务首屏；失败必须留下可重试诊断，Remote 失败不得静默切换 Local。
- 所有计数和状态使用同一领域快照语义；前端不得从文件数、历史数或“插件已启用”推导已学习数量或健康状态。
- Dashboard 优先复用现有 AntD 组件和项目既有间距、颜色、排版与交互，不新增视觉框架。
- 修改 Runtime 或生成资产时按仓库规则重新构建并校验对应产物；验证范围与跨模块改动风险匹配。
- 本 change 使用从最新 `origin/master` 创建的 `hotfix0903` 分支和独立工作区，只纳入本 change 的正式产物与实现。

# 决策

- 使用一个 Native change 完成闭环，不拆成 Supervisor Change；学习、状态和展示共享同一语义，分开实现会增加漂移风险。
- 先修学习链路、权威状态和反馈闭环，再整理数据和界面；Dashboard 不为错误状态做表面包装。
- 有效知识定义为 `trial | proven | enforced`，历史定义为 `superseded`；tombstone 是遗忘保护，不是有效记忆。
- 知识版本以稳定逻辑身份和内容摘要决定，文件修改时间只作提示信息。
- 任务、CLI 和 Dashboard 共用项目知识的 ensure/refresh 服务；读取状态不得与实际任务启动后的状态不一致。
- 显式长期意图一次即可 proven；稳定但未明确长期保存的协作习惯先进入 trial；一次性指令不持久化。
- 项目语义策略必须接入真实生产审查边界；不可用时延迟而不是生成泛化占位策略，并提供可见诊断和重试。
- application outcome 只来自实际使用结果；未反馈与失败必须和成功分开统计。
- 个人记忆页面以记录为中心，项目知识页面以知识单元为中心；文件只是来源或投影，不作为“学到多少”的替代指标。
- UI 使用现有 Dashboard 的克制、紧凑风格，以清楚的名词、状态和操作表达，不使用营销化或拟人化 AI 表达。
- 现有异常数据在代码路径修复后再迁移/重建，避免清理后再次产生相同重复项。
