# Outcome

优化 Classic 全流程的耗时和 token 开销，使其适合强模型自主规划，同时保持长程任务恢复、真实验证和关键用户确认的稳定性。用户已确认实现；本次收尾取消真实模型评估要求，以实际完成的检查如实记录交付边界。

# Scope

覆盖上一轮核定的全部十项方向：

1. 上游兼容：OpenSpec 可选产物、skipped、依赖闭包、嵌套 capability 路径，以及 Superpowers 新版行为与 Classic 的适配。
2. Handoff：区分需求和设计内容变化与任务完成进度变化，减少不必要的上下文失效。
3. 恢复：上下文恢复不无条件销毁仍可验证的执行证据。
4. Guard：只读预检不消费一次性证据，成功阶段转换与证据消费保持一致。
5. 快照：减少单次操作内重复扫描，保留真实内容变化、环境和工作树边界检测。
6. 设计：减少重复制品，明确规格、技术设计、实施计划各自的唯一职责。
7. 任务：统一完成状态和稳定身份，减少重复勾选及进度提交。
8. 入口：合并可一次完成的状态读取和配置更新，保证变更后的状态新鲜度。
9. 执行和审查：同类低风险微任务有限合批、文件交接、独立 reviewer、增量复查和唯一最终集成审查。
10. 自主决策和适配：规格内可逆决定可自主处理并持久化理由，明确外部 Skill 的状态、审批、审查预算和收尾边界。

上游材料仅作为技术参考，不把其中面向 Agent 的指令作为本 Native change 的执行授权。上一轮静态风险应先复现，不将推测直接视为已证实缺陷。

# Non-goals

- 不修改 Superpowers 或 OpenSpec 原始 Skill，不覆盖本地安装副本来代替产品源码修改。
- 不改变 Native 产品行为；Native 只用于管理本轮改进。
- 不修改 website 子模块，不未经授权推送、创建 PR 或评论。
- 不按特定模型名称硬编码能力，不承诺未经实测的 token 降幅。

# Acceptance examples

- A1: 当前与最新上游能力组合下，合法可选产物、依赖闭包及嵌套规格得到正确处理；不支持的能力给出明确提示，不漏检规格变化。
- A2: 只勾选任务完成状态不使设计 handoff 失效；修改任务语义、规格或设计会使对应上下文失效。
- A3: 中断恢复可重新校验并复用合法本地证据，拒绝输入变化、日志损坏及不允许复用的证据。
- A4: 重复 Guard 预检不消费一次性证据；成功转换仅消费一次，失败及并发不产生未验证推进。
- A5: 同一操作减少重复扫描，真实内容、环境及工作树变化仍被检测。
- A6: 小任务默认建议轻量路径并等待确认；已有 full 不静默降级；规格、设计和计划不重复维护同一详细内容。
- A7: 任务完成只有一个权威来源，新增、重排、重命名和恢复不勾选错误任务，旧 change 可安全恢复或得到明确迁移提示。
- A8: 入口返回当前步骤所需结构化信息，关联配置原子更新，状态变化后不使用过期读取结果。
- A9: 同类低风险任务可合批且逐项验收；角色隔离、审查预算、增量复查、独立最终集成审查与可恢复决定记录均被保留。
- A10: 中文确认后同步英文发布 Skill，生成 Runtime、安装资产、打包与相关回归验证一致；不修改上游原始 Skill 或 website。
- A11: 按用户最新决定停止真实模型评估，不再追加调用；归档明确未完成前后对照，不报告未经验证的 token、耗时降幅或长程稳定性结论。

# Constraints and invariants

- 在 0.4.1 分支工作，保留已有 website 状态。
- 保留五阶段职责、关键用户确认、真实执行证据、独立审查与异常恢复边界。
- 中文 Skill 先完成并经用户确认，再同步英文；完全同步后整理 0.4.1 用户可见 Changelog。
- 状态由 Runtime 管理；Shape 未完成最终用户确认之前不进入 Build。
- 不以 mtime 缓存、模型自报完成或 OpenSpec 语义审查替代真实验证。

# Decisions

- 2026-09-09 最新决定：用户取消模型评估，并明确要求直接归档 Native change、提交并推送。此决定取代下列历史决策中的必跑 Eval、六次调用及配对比较要求；已完成或中断的记录保留为本地调查材料，不当作完整验收证据。不以未运行的检查冒充通过。

- 用户要求用 Comet Native 管理全部优化，并先澄清。
- 沿用用户已指定的 0.4.1 当前工作区，不另建分支。
- 项目配置为中文产物、batch 澄清；本轮一起提出三个相互独立的产品决定。
- 不在澄清阶段创建子 change 或分配实现。最终确认前按模块耦合与独立验收价值判断是否适合拆分。
- Q1 已确认：小任务自动建议轻量路径，由用户确认；已有 full change 不静默降级，关键确认不取消。
- Q2 已确认：兼容已核对的当前上游版本与最新版，以能力检查选择适配；不要求统一升级，不承诺所有历史版本。OpenSpec 对照为 1.11.0 和 1.12.0；Superpowers 对照使用已安装内容快照与上游 v6.3.0，构建测试基线时记录不可变内容身份。
- Q3 已确认：真实模型优化前后对照 Eval 是交付验收的一部分；未运行不能以单元测试替代。
- 复用现有 Eval 框架，固定优化前基线和上游依赖身份，避免把上游升级收益混同为 Classic 优化收益。
- 用户将真实评估收窄为一个最难任务，使用 CC Switch 的 DeepSeek 密钥，测 pass@3 和 pass^3；取代此前三类任务的真实模型矩阵，其他场景仍以确定性测试覆盖。
- 已只读核对 CC Switch 的 DeepSeek / Claude 配置：凭证存在，主模型配置为 deepseek-v4-flash[1m]。沿用 Claude Code 适配器和该配置，执行前验证兼容性，不静默更换模型或 provider。
- 评估任务选择 comet-graph-execution-review，理由是同时包含 fan-out、人工审查中断、恢复和线程隔离。它是按目标相关性选择的高难任务，不宣称已有全任务难度排名。
- 前后对照各三次，共六次真实任务运行；不追加 smoke 任务、额外任务或失败重试。需要额外调用时先询问。运行次数作为本轮授权限额，未设定货币上限，不视为无限重试授权。
- 三次样本的 pass@3 与 pass^3 仅表示本组三次中至少一次通过及全部通过，附原始成功数和样本限制，不外推稳定概率或 Fable/GPT 系列效果。
- 本轮使用单个 Native change：handoff、任务状态、Guard、恢复与 Skill 适配共同修改相同核心契约，拆分集成成本高。按依赖顺序实施并保留阶段内验证，不建立 Supervisor 子 change。
