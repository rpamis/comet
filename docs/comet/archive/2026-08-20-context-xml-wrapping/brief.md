# 目标

让 Agent 能稳定区分自动注入的个人记忆与项目知识，同时保留现有召回内容、顺序、数量和失败语义。

# 范围

- 在统一的插件上下文注入边界包装个人记忆贡献。
- 在同一边界包装项目知识贡献。
- 对包装体内的 XML 特殊字符做安全转义，并为两类贡献增加回归测试。

# 非目标

- 不修改个人记忆或项目知识的召回算法、过滤条件、排序、数量上限或渲染正文。
- 不修改插件启用/停用、Dashboard、配置开关、诊断持久化或远程 Provider 行为。
- 不为未知插件贡献添加猜测性的标签，也不改变插件失败的非阻塞语义。

# 验收示例

- A1：个人记忆贡献以单个 `<personal_memory>...</personal_memory>` 元素返回，正文和现有 Markdown 换行保留。
- A2：项目知识贡献以单个 `<project_knowledge>...</project_knowledge>` 元素返回，正文和来源引用保留。
- A3：贡献正文中的 `&`、`<`、`>`、`"`、`'` 被转义，生成的上下文可作为 XML 文本安全传递。
- A4：空贡献不生成空标签；未知插件贡献保持原文，且贡献数量和顺序不变。
- A5：个人记忆和项目知识仍沿用现有桥接、配置策略和非阻塞错误处理；相关测试覆盖包装边界且无既有回归。

# 约束与不变量

- 稳定标签固定为 `personal_memory` 和 `project_knowledge`，不得由显示名称或用户输入生成。
- 包装发生在插件桥完成合并之后，因此每类插件贡献最多一个顶层标签。
- 只包装非空的两个已知插件贡献；不改变未知插件的文本。
- XML 转义只作用于贡献正文，不能改变标签名称或插件 ID。
- 代码和测试遵循现有 TypeScript、Vitest、Native runtime 生成物和 Changelog 约束。

# 决策

- 采用 `<personal_memory>` 表示个人记忆，采用 `<project_knowledge>` 表示项目知识；用户已确认。
- 在 `collectCometPluginContext` 的公共注入边界统一包装，而不是让两个插件各自重复包装。
- 空白正文视为空贡献，不发出空 XML 元素；其他已存在的错误仍只记录诊断并继续任务。
