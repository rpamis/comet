# Outcome

让用户在 Comet Dashboard 中直接管理“个人记忆”和“项目规则”两个第一方插件。两个页面使用插件 Runtime 的公开页面和能力接口，和 Skill、CLI 共享同一份领域数据；页面只是管理入口，不复制记忆、规则或插件状态。

# Scope

- 在 Dashboard 主侧边栏提供独立的“个人记忆”和“项目规则”入口；入口不属于 Classic、Native 或某个 change。
- 个人记忆中心页展示当前画像、当前项目记忆、最近检索摘要、学习/检索开关、Git 同步状态，并支持纠正、删除、回滚和同步重试。
- 项目规则中心页展示初始化状态、上次盘点、规则来源、原生验证入口和候选；支持初始化、重新扫描、加入、忽略、稍后和恢复。
- 页面通过 `PluginRuntime.dashboardPages()` 发现插件，通过 `PluginRuntime.invoke()` 调用公开能力；页面加载或能力调用失败只隔离到对应插件页。
- Dashboard Server 提供页面列表、页面数据和能力调用的 HTTP 接口；现有 workflow 页面和只读变更接口保持兼容。
- 已安装但停用的插件仍显示入口和启用操作；卸载后入口消失，插件数据、项目规则和原生检查配置保留。

# Non-goals

- 不重新实现个人记忆或项目规则领域逻辑，不创建 Dashboard 专属记忆、规则或候选文件。
- 不修改 Native、Classic、Hotfix 或 Tweak 状态，不创建 Comet change，不执行项目编译、linter、测试或 Git 推送。
- 不实现第三方插件安装包、Skill/CLI 文案或 Hook；这些能力由插件 Runtime 和宿主集成提供。

# Acceptance examples

- 用户打开 Dashboard，侧边栏同时看到“个人记忆”和“项目规则”；切换入口后中心页保持现有 Dashboard 的紧凑 AntD 视觉语言。
- 个人记忆插件不可用时，个人记忆页显示可读诊断，项目规则页和 workflow 页面仍能打开。
- 用户在个人记忆页纠正一条画像、删除一条项目记忆、点击回滚或同步，刷新页面后结果来自同一记忆仓库；页面不保存副本。
- 用户在项目规则页对未初始化项目点击“初始化”，只得到盘点摘要；点击“重新扫描”更新来源和验证入口；对候选执行加入、忽略或稍后与 Skill/CLI 语义一致。
- 停用插件后页面保留停用状态和启用按钮；卸载后侧边栏入口消失，但记忆文件、规则文件和原生检查配置仍保留。
- 插件页面加载异常、能力调用异常或返回无效数据时，其他页面继续可用并显示对应插件诊断。

# Constraints and invariants

- 插件页面只依赖 `comet-plugin` 公开接口和个人记忆/项目规则公开能力；不得读取另一个插件的私有 Runtime。
- 页面展示默认只使用用户可读摘要；候选内部 ID、评分、证据时间戳和 Runtime 状态机字段不进入普通页面。
- 页面动作调用与 Skill、CLI 相同的领域服务，成功后重新读取服务结果；不维护第二套状态。
- 所有页面数据和操作响应有固定大小上限；失效项目、停用插件和宿主错误都返回结构化、可理解的诊断。

# Decisions

- 使用 Dashboard 插件页面贡献作为侧边栏来源；首批两个第一方页面采用稳定的 `personal-memory` 与 `project-rules` 路由。
- Server 在项目路径下按现有 `/api/dashboard/projects/:id/...` 组织插件接口，前端只保存当前页面选择，不保存领域数据。
- 页面操作统一通过 `invoke` 能力名进入插件；插件生命周期操作仍由 Runtime 管理。

# Open questions

- 第三方插件自定义页面的复杂渲染格式留给后续 Design；本 child 只支持首批两个第一方页面需要的摘要和操作。

# Verification expectations

- 运行 Dashboard 插件 Host、Server API、现有 Dashboard Server 测试和前端类型/构建检查。
- 覆盖两个页面同时出现、单页失败隔离、停用/卸载入口语义、初始化/扫描/候选操作以及页面刷新后状态来自领域服务的场景。
