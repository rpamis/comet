# Outcome

在保持最终交付正确率的前提下，极致压缩 Native Verify 耗时与 token。实现 Verify 内的可选 bugfree 模式，由一个独立前沿 Agent 主导语义审查、自主选择必要验证、紧凑回报和合格增量续审。

# Scope

完整实现来源第1—19节的产品、协议兼容与确定性验证要求。准备评估场景和指标；真实模型对照须用户另行明确授权场景、样本和轮次，未授权保持待验证。来源第20节只是此前文档任务记录。

# Verification expectations

先最小定向测试，再相关契约、lint、编译、生成物、公开 CLI、npm 包及当前平台独立会话验证。未授权 Eval 时完成评估准备并保留模型正确率/成本证据缺口，不声称目标已验证。中文 Skill 修改文本确认后再同步英文。

# Acceptance examples

- 配置省略、两种合法值：缺省 standard，合法值往返不变。
- 非法配置类型和值：明确拒绝，不能静默退回 standard。
- init/update/配置合并：保留模式、未知字段及未涉及配置；不恢复预算字段。
- 新 Run 创建：从项目配置固定模式，状态和 Shape 展示相同。
- 旧 Run 与旧定义：缺字段继续 standard；伪造 bugfree 字段不能改变旧定义。
- 中途修改配置：当前 Run 模式不变，新 Run 使用新值。
- checkpoint 恢复：保留原模式、候选、Action 和审查来源；不读取本机模式替代。
- 普通候选空命令计划：零子进程检查，仍有候选绑定，必须等待独立 Verifier。
- standard 行为：原检查模板、完整结果校验及新候选独立审查语义不被放宽。
- 主 Agent 冒充 Verifier：相同 Builder 身份、参与过实现的会话或错误 claim 均不能通过。
- 同一候选重复派发：已运行/未知 Action 不产生第二个正式 Verifier。
- 紧凑全部通过：明确 ID 完整覆盖才通过，报告按实际方法生成。
- 紧凑集合异常：漏项、未知 ID、重复、交叉重复、混用 passed 均拒绝。
- 总 verdict 与逐项不一致：按第 10 节规则拒绝，不能靠总 pass 补齐结论。
- 完整旧结果：旧格式仍可读；standard 不接受 bugfree 专用字段。
- 必需检查失败：紧凑 pass 仍被拒绝；旧成功、换 ID 和删除计划不能掩盖当前失败。
- 真实检查复用：复用原 Action 和日志，保持环境、计划与完整输入校验。
- 同候选补查：原会话继续，检查只执行请求集合，不扩为全量。
- 两轮补查上限：沿用原上限，未解决问题不能自动通过。
- 修复后续审：新 Action 绑定新候选；符合条件时建议原会话，覆盖全部验收 ID。
- 续审不满足条件：会话丢失、参与修改、需求变化、工作区变化时选择 fresh。
- 用户要求重新验收：新 attempt 使用新独立上下文，保留原历史。
- 输入缺失或漂移：不完整快照、并发改写、正式需求漂移均不能通过。
- 报告失败恢复：不重新调用模型，恢复原报告 Action。
- 接受与 Archive：未接受不归档；接受后继续核对绑定；未知副作用不重放。
- Supervisor 作用范围：仅父级最终 Verify 启用；Child/集成原要求不变。
- Native 扩展应用：扩展步骤仍执行，旧固定应用不被配置升级。
- 精简任务包：无 Builder 自评、完整聊天和成功日志正文；需求、失败及所有验收项仍可取得。
- 任务包变化范围：首次覆盖 change 全部实现差异；续审另提供相邻差异，包含删除/重命名/未跟踪文件。
- 报告事实：零命令不写测试通过；复用不写新执行；模式、方法和结果一致。
- 公开 CLI 与 bundle：新建、领取、回报、补查、接受、恢复均从公开入口完成。
- 安装包：临时项目安装实际 npm 打包产物后配置生效，未携带仓库源码仍可运行。
- 平台独立会话：平台真实创建和恢复会话；身份独立，等待超时不重派。
- 历史与其他 workflow：Compat、Classic、历史 archive 和旧 SDK checkpoint 保持原行为。
- 修复后处理前轮诊断失败：用户要求的执行检查仍需真实通过；自主诊断失败可由独立 Verifier 确认语义修复，历史失败不得被隐藏或写成测试通过。
- 模型对照授权与证据边界：遵守来源第16节；未获明确授权不启动 Eval，准备冻结案例、独立判定和指标采集；未执行时保留待验证状态，不宣称正确率或性能收益。
- 产品文档与发布资产：按来源第17—18节同步正式规格、中文及经确认的英文 Skill、配置说明和 Runtime 生成资产；根据实际 master/tag 决定版本与英文 Changelog，分别记录各验证层级。
