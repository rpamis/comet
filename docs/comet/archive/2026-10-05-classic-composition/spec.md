# comet-any SDK 工作流创作与执行

本规格描述重建完成后的完整目标行为，覆盖需求来源 R01 至 R26。Q1 至 Q7、完整产品范围和推进 A（多会话协作）已确认；本次按用户补充，将真实宿主与模型验收限定为 Claude Code，保留七个 Child 和全部产品能力。

## 决策状态

- Q1：产品支持 Codex 与 Claude Code；2026-10-04 的用户补充将本轮真实宿主与模型验收限定为 Claude Code，产品组合能力和流程范围保留。
- Q2：按用户“不必考虑旧版，没人使用”的明确说明，不保留旧生成链兼容、旧版维护或迁移工具；旧格式提示重新生成，不自动删除用户文件。
- Q3：Native 扩展覆盖普通执行、Supervisor 父级、Child 和集成验收全链路。
- Q4：支持本地工作，以及可查询或具备核对适配的外部操作；未知结果先核对，不盲目重试。
- Q5：支持项目级安装、用户级安装和完整包导出。
- Q6：不建设远程分发；按 Q5 提供本地交付。

- Q7：采用分阶段验收，真实宿主与模型仅在 Claude Code 验收。使用 CLI 2.1.251、glm-5.3[1M]，主代理和子代理同模型；六种正式流程各重复 2 次，共 12 个样本，最多并行 1 个，总时限 10 小时。前置 Native 样板独立限时 1 小时；追加预算须取得用户决定，不重置原记录。全部规定样本通过的要求保留。

Supervisor 推进方式随完整 Shape 最终确认。

## Requirement: R01 用户目标与交付物

comet-any 根据用户目标和真实 Skills 生成可调用的工作流 Skill。支持基于 Native 增加流程、调整 Classic Skill 编排，以及创建独立工作流；交付完整 Workflow Application 包和实际验证结果。

### Scenario: R01 验收

Acceptance: A1

- WHEN 用户按该条声明的输入、执行条件或异常条件运行工作流。
- THEN 三种起点均能形成可运行的 Application 包；入口 Skill 能启动并继续对应流程，展示实际验证范围。

## Requirement: R02 职责与运行权威

SDK Run 是一次执行唯一可推进的权威状态。comet-any 负责理解与创作，组合器负责装配应用，Native 和 Classic 各自负责业务规则，宿主负责推理、工具和交互。生成包不得复制另一套状态机。

### Scenario: R02 验收

Acceptance: A2

- WHEN 用户按该条声明的输入、执行条件或异常条件运行工作流。
- THEN 从入口、CLI 和恢复入口访问同一 Run；修改说明文件或投影视图不能绕过已声明的执行规则。

## Requirement: R03 应用加载与归属

应用具有独立身份，加载时固定定义、执行绑定与验证器版本；CLI、当前 change 选择、Hook 和状态诊断能找到同一应用与 Run。不得仅改工作流名称而沿用仅接受内置应用的恢复判断。

### Scenario: R03 验收

Acceptance: A3

- WHEN 用户按该条声明的输入、执行条件或异常条件运行工作流。
- THEN 定制应用经公开入口启动、查询和继续均路由正确；同名不同项目或 worktree 不会串用 Run。

## Requirement: R04 定义与依赖固定

固定工作流、Skill 内容及其引用资源、适配契约、验证器和所需 Runtime 的版本或摘要。活动 Run 使用原定义；缺失或内容漂移时给出可操作的恢复说明，不静默换用新实现。

### Scenario: R04 验收

Acceptance: A4

- WHEN 用户按该条声明的输入、执行条件或异常条件运行工作流。
- THEN 修改同版本定义、依赖 Skill 或资源后，活动 Run 拒绝按新内容继续；恢复原依赖后可以沿原记录恢复。

## Requirement: R05 动作与恢复协议

复用 SDK 的 Action 领取、尝试、Outcome、Wait、revision 和并发提交机制。未满足依赖的越序回报、错误归属、陈旧确认和冲突回报被拒绝；合法派发的独立并行 Action 可按任意完成顺序回报。重复的同一合法结果按协议幂等处理；未知执行必须核对后继续。

### Scenario: R05 验收

Acceptance: A5

- WHEN 用户按该条声明的输入、执行条件或异常条件运行工作流。
- THEN 未满足依赖的越序回报、旧 attempt、错误 Action 归属和陈旧提案不能推进；合法并行 Action 可按任意完成顺序回报；断连后保留原 Action，已发生的外部操作不被自动重发。

## Requirement: R06 Native 新增流程

Native 保留自身实现和默认无外部 Skill 依赖的主流程。定制应用可以在明确的业务位置增加可独立恢复的步骤；新增必需步骤通过后才能推进原流程，默认 Native 行为保持不变。

### Scenario: R06 验收

Acceptance: A6

- WHEN 用户按该条声明的输入、执行条件或异常条件运行工作流。
- THEN Native 样板增加候选审查后，未通过审查不能进入后续验收；未配置扩展的 Native 不新增外部 Skill 依赖。

## Requirement: R07 Native 执行指导

允许给 Builder 等实际工作附加指导 Skill，声明作用范围并把所需内容传给执行者。加载记录与产物符合规范的验收分别保存，不能以加载声明代替质量检查。

### Scenario: R07 验收

Acceptance: A7

- WHEN 用户按该条声明的输入、执行条件或异常条件运行工作流。
- THEN Builder 获得指定版本的指导和范围；产物违反可检查的指导要求时，即使已经加载 Skill 也不能通过对应验收。

## Requirement: R08 Native 验收与修复

新增检查绑定当前候选和输入工件；候选或相关输入变化时相应证据失效。业务审查失败进入明确修复路径，保留现有工作；不绕过 Native 的确认、独立 Verify、交付和 Archive 条件。

### Scenario: R08 验收

Acceptance: A8

- WHEN 用户按该条声明的输入、执行条件或异常条件运行工作流。
- THEN 审查失败可回 Build 修复；新候选重做已失效的检查；额外审查通过不能直接跳过 Native 独立验收或取得交付授权。

## Requirement: R09 Native 需求变更

新增步骤改变已确认需求、设计工件或验收条件时，遵循基础应用重新校验和确认路径。纯实现修复与需求变化分别处理，不能错误复用旧授权。

### Scenario: R09 验收

Acceptance: A9

- WHEN 用户按该条声明的输入、执行条件或异常条件运行工作流。
- THEN 扩展引入需求变化会返回 Shape 重新确认；未改变确认范围的实现修复沿修复流程继续。

## Requirement: R10 Native Supervisor 产品覆盖

生成的 Native 扩展覆盖普通 Native、Supervisor 父级、Child 和集成验收全链路。新增步骤、执行指导、附加验收和恢复要求必须传递到实际执行层，不能仅在父级生效。

### Scenario: R10 验收

Acceptance: A10

- WHEN 用户按该条声明的输入、执行条件或异常条件运行工作流。
- THEN 普通 Native、Supervisor 父级、Child 和集成验收中的扩展均有效；跨会话继续仍保留要求，父级加载一次 Skill 不能代替 Child 的执行与验收。

## Requirement: R11 Classic Skill 编排

Classic 支持替换符合原工作契约的 Skill 绑定、增加步骤和调整允许的顺序。保持所选 full、hotfix、tweak 流程必要工件、授权、验收和恢复规则；不修改第三方原始 Skill。

### Scenario: R11 验收

Acceptance: A11

- WHEN 用户按该条声明的输入、执行条件或异常条件运行工作流。
- THEN 定制 Classic 在各受影响 profile 中可完成真实流程；无效替换或顺序变化被解释并拒绝，不用文本成功声明替代领域验收。

## Requirement: R12 Classic 失败与恢复

Classic 定制工作仍由其 Application 与 SDK 推进。失败修复、需求修订、工件失效、审批与中断恢复沿同一 Run 执行，组合步骤不能在基础流程之外独立放行。

### Scenario: R12 验收

Acceptance: A12

- WHEN 用户按该条声明的输入、执行条件或异常条件运行工作流。
- THEN Classic 新增或替换的工作发生失败、工件变化和中断时可恢复；基础命令不能绕过组合应用新增的必需检查。

## Requirement: R13 独立工作流

支持不依赖 Native 或 Classic 阶段的独立应用，使用 SDK 表达顺序、分支、明确 join、子工作流和有界修复；业务规则由自身定义。以报告生成、用户审批和发布为完整样板。

### Scenario: R13 验收

Acceptance: A13

- WHEN 用户按该条声明的输入、执行条件或异常条件运行工作流。
- THEN 独立报告流程在审批前不发布，拒绝或修改后走声明路径，跨进程继续同一 Run；不宣称自动继承 Native 独立验收语义。

## Requirement: R14 真实 Skill 发现与适配

读取 Skill 的真实说明、脚本和必要资源，区分执行指导、产出动作、检查动作、完整子流程。适配契约声明输入、输出、范围、宿主能力、用户交互、结束条件、失败与恢复；名称不能代替能力调查。

### Scenario: R14 验收

Acceptance: A14

- WHEN 用户按该条声明的输入、执行条件或异常条件运行工作流。
- THEN 真实内容不支持所要求能力、依赖缺失或输入输出不匹配时不能生成虚假可运行承诺；第三方原文件不被改写。

## Requirement: R15 冲突与证据能力

识别多个 Skills 对职责、工件、确认、工具和副作用的冲突。完整外部流程必须显式适配为子工作流或可隔离工作。不能保证的行为如实说明，必需且无法满足的能力阻止运行。

### Scenario: R15 验收

Acceptance: A15

- WHEN 用户按该条声明的输入、执行条件或异常条件运行工作流。
- THEN 含有自行发布或接管审批逻辑的 Skill 不能作为普通指导绕过父流程；加载、自报完成、机器检查和独立评审能被区分。

## Requirement: R16 确定性应用组合

在用户确认的方案和固定依赖下，装配流程定义、纯转移处理器、执行绑定、验证器和恢复身份。按同一组合结果生成入口说明和安装内容；不只修改图而沿用不匹配的转移处理器。

### Scenario: R16 验收

Acceptance: A16

- WHEN 用户按该条声明的输入、执行条件或异常条件运行工作流。
- THEN 相同方案与依赖生成一致的有效产物；未声明转换、缺失验证器及重复或冲突身份在执行前被发现。

## Requirement: R17 输入输出与候选验证

Schema 必须真正校验结构，业务验证器核对实际产物、当前候选和内容摘要。只存在文件、存在字段或自行填写 completedChecks 不能等同于验收通过。

### Scenario: R17 验收

Acceptance: A17

- WHEN 用户按该条声明的输入、执行条件或异常条件运行工作流。
- THEN 非法 JSON、缺失必填数据、过期工件、错误候选和伪造完成字符串无法满足相应检查；拒绝后保留现场并给出修正动作。

## Requirement: R18 Creator 可恢复创作

comet-any 自身使用固定的 SDK 创作流程，保存目标、方案、决定、依赖和产物之间的关联。完成分析、确认、编译、验证和交付；子代理按工作量组织，不要求固定六个角色。

### Scenario: R18 验收

Acceptance: A18

- WHEN 用户按该条声明的输入、执行条件或异常条件运行工作流。
- THEN 在方案确认或编译验证期间中断后能继续同一次创作；方案变化使受影响的确认和验证失效，不重复执行已明确完成的外部工作。

## Requirement: R19 用户体验与确认

向用户展示具体步骤、绑定 Skill、产物、验收、失败路径和能力限制，内部 Bundle、注册和协议名不作为使用前提。确认绑定当前方案，安装前展示目标与文件变化，沿用已有有效授权。

### Scenario: R19 验收

Acceptance: A19

- WHEN 用户按该条声明的输入、执行条件或异常条件运行工作流。
- THEN 用户能从自然语言需求完成创作；看到实际流程和安装预览；方案或安装目标漂移时原确认不能被复用。

## Requirement: R20 宿主执行与平台支持

产品支持 Codex 与 Claude Code 的宿主适配。宿主加载固定版本 Skill、领取和执行 Action、传递必要上下文、取得用户决定并提交真实结果。按用户 2026-10-04 的补充，本轮真实宿主和模型验收只在 Claude Code 执行；其他安装平台不计入本轮正式支持范围，Codex 的真实模型执行不计入本轮完成条件。

### Scenario: R20 验收

Acceptance: A20

- WHEN 用户按该条声明的输入、执行条件或异常条件运行工作流。
- THEN Claude Code 完成真实 Skill 调用、必要交接和中断恢复；必需能力缺失时明确阻塞，不静默跳过。Codex 适配保留对应的本地契约与回归检查，报告明确未执行其真实宿主和模型验收。

## Requirement: R21 外部操作与凭据

支持只读、本地工作区修改，以及可查询或具备核对适配的外部操作；首版不执行无法核对结果的外部操作。任何操作都不能扩大用户授权；外部操作和本地 Run 不假设原子提交，未知结果按适配契约核对后继续。凭据只由执行上下文注入，不进入包、Run、报告或生成配置。

### Scenario: R21 验收

Acceptance: A21

- WHEN 用户按该条声明的输入、执行条件或异常条件运行工作流。
- THEN 外部操作结果丢失后可按适配契约查询或核对，不盲目重复发送或部署；没有核对能力时明确阻塞；产物和持久化记录不包含凭据。

## Requirement: R22 安装分发与升级

支持项目级安装、用户级安装和完整包导出，不建设远程 Git 发布安装或团队集中分发服务。安装提供预览、依赖检查和冲突处理；新 SDK 应用的活动 Run 所需旧定义保持可用，升级不静默迁移，卸载不能悄悄破坏在途任务。

### Scenario: R22 验收

Acceptance: A22

- WHEN 用户按该条声明的输入、执行条件或异常条件运行工作流。
- THEN 真实导出包在项目级与用户级目标安装后均可启动和恢复；同名冲突、升级与有活动 Run 的卸载按明确规则处理；不要求远程分发服务。

## Requirement: R23 旧生成链退出

用户已明确不必考虑旧版使用。移除旧生成链，不为已发布旧包、workflow-protocol 状态或旧在途 Run 保留兼容层、旧版维护及迁移工具。新产物只使用 SDK 应用链；遇到旧格式时明确提示重新生成并保留用户文件。该决定不取消 R22 对新 SDK 应用自身升级和活动 Run 的保障。

### Scenario: R23 验收

Acceptance: A23

- WHEN 用户按该条声明的输入、执行条件或异常条件运行工作流。
- THEN 新产物只走 SDK 应用链，产品不再依赖旧生成和推进逻辑；旧格式被明确拒绝并提示重新生成，不被静默加载或自动转换，用户文件不被自动删除。

## Requirement: R24 分层生产验收

分阶段完成定义检查、定向测试与故障注入、生成 Runtime、npm 打包消费者、真实宿主 Hook/交接及真实模型 Eval，并分别记录绑定当前候选与依赖的证据。Claude Code 覆盖 Native 普通与 Supervisor、Classic full/hotfix/tweak、独立流程，以及对应的创作、安装、执行与恢复；覆盖失败修复、中断恢复、候选或依赖漂移和旧确认失效。外部操作在隔离服务中验证已执行但回传中断与确认未执行两类恢复。本轮使用 Claude Code 2.1.251、glm-5.3[1M]，主代理与子代理同模型，正式矩阵六种流程各重复 2 次，共 12 个样本，最多并行 1 个，总时限 10 小时；Native 前置样板独立限时 1 小时，不计入正式矩阵。实际模型以进程轨迹为准，不能把费用遥测当金额硬限。规定样本必须全部通过，保留失败及超时记录，不以多次中的一次成功代替全通过；候选变化后重验受影响部分，仍匹配的证据可复用。预算到限或环境不可用的项目保持未完成；追加预算须取得用户决定，不重置已有记录。

### Scenario: R24 验收

Acceptance: A24

- WHEN 用户按该条声明的输入、执行条件或异常条件运行工作流。
- THEN Claude Code 的全部指定流程及恢复场景在当前候选上满足已确认矩阵中的所有规定样本；外部结果核对后操作计数为一；未运行、失败、超时或缺少真实宿主及模型证据时不能完成生产验收。

## Requirement: R25 实施顺序与不回归

按契约、Native 垂直样板、Native 扩展、Classic 与独立流程、组合器、Creator、分发验收七步推进。宿主执行、授权与未知结果核对契约在基础阶段确定；第一个样板同时验证公开入口、参考宿主真实 Skill 执行和冷恢复；默认 Native、Classic 和既有 SDK 消费者保持有效。

### Scenario: R25 验收

Acceptance: A25

- WHEN 用户按该条声明的输入、执行条件或异常条件运行工作流。
- THEN 先完成能运行、失败可修复和冷恢复的 Native 样板，再扩展生成能力；基础应用和 SDK 既有契约通过相关回归检查。

## Requirement: R26 文档与发布范围

中文需求与 Skill 先完成并确认，再同步英文；README 仅保留必要入口并链接详细文档。按最终用户可见变化写英文 Changelog，发布前核对 master 和当前版本；保留无关修改，不改 website 或第三方原 Skill。

### Scenario: R26 验收

Acceptance: A26

- WHEN 用户按该条声明的输入、执行条件或异常条件运行工作流。
- THEN 产品文档与真实行为一致；中英文 Skill 同步后再更新对应发布说明；检查与修改范围可追溯。

## 完成与变更

所有有效需求均须由本 change 的真实验收项覆盖。用户澄清导致行为变化时，先更新本规格及 brief，再重建受影响的 Child 契约。新增范围、当前候选与确认漂移不能通过修改 Runtime 状态绕过。
