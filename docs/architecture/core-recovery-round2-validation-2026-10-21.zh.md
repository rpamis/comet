# 第二轮核心恢复与并发修复验证（2026-10-21）

比较基线：`67d6579f7ede4e719ee004adea15eee7d9a5a0c4`（050）。保持开发版本 0.5.0；本轮开始时 master 和最新发布 tag 均为 0.4.5。提交与推送代码不等同于发布 npm 包或通过正式版验收。

## 修复范围

1. Classic 检查的正常退出与超时都经过受管进程监督。命令退出不再直接证明后代已停止；确认清理与静止后才采集最终输入快照，无法确认时保留未知执行和写入保护。
2. Eval 管理端保存首次停止时间，独立于 worker 的轮询监督停止宽限期和执行预算。按登记的创建身份处理 owner、独立执行子树及容器；清理失败保留可诊断状态，不把取消请求当作已停止。排队时间不消耗执行预算。
3. Dashboard 的应用存储发现按分区隔离异常。损坏分区保留错误条目，健康应用继续发现；当前 Run 目录名称、类型和元数据参与指纹，错误摘要可重新读取，修复后不必修改 checkpoint 才能刷新。
4. Native 已完成检查的输入发生漂移时，只在原结果、计划、日志仍可信且执行已静止后，允许用原领取绑定的真实停止证明进入新候选修复审批。不能复用旧成功、自动重跑原检查，或把日志损坏解释为输入漂移。
5. 同一 canonical projectRoot 的应用使用工作区、应用、Run 的固定锁顺序，按各自固定 manifest 核对实际占用范围。未知执行和未确认停止的取消继续占用；跨应用同名 Run 不会被当作自身跳过。独立成员清单和写前占用身份保留防止应用目录缺失时遗忘原占用；合法 portable checkpoint 恢复保留未知执行，多 Run 恢复补齐已知占用后才重新绑定目录。
6. 普通 Skill 入口通过校验后的只读投影读取当前状态，避免预先物化全部历史；终态输出省略必须明确标记，并提供完整查看和分页历史入口。完整 inspect API 保留。

## 验证记录

- 原始 Classic 复现已用构建产物回放：检查成功返回后继续等待，源文件保持原内容，残留后代不再延迟修改源码。测试使用独立临时数据目录；早先默认 HOME 只读导致的未执行结果不计入通过。
- Dashboard 三份原始复现回放通过：坏分区存在时仍发现健康新增 Run；目录污染后暖缓存显示不可读；移除污染后原缓存恢复正常，无需修改 checkpoint。
- 保留的 100 Action Skill 样本响应由 106,179 字节变为 1,630 字节，完整证据仍可显式读取。最终当前视图测试核对历史物化数为 0。最终构建产物的一次采样约 611 ms、瞬时堆增量约 29.4 MiB，未显示可信的耗时或内存改善，不据此宣称百分比提速或无泄漏。
- 本地规模样本覆盖 100/1,000 个文件、0/10 个脏文件、10 项验收、10/100 Action；每场景预热 1 次、测量 2 次，显式快照文件预算为 2,000，快照均完整。1,000 文件的 Native 全量快照中位数约 279 ms，干净增量约 92 ms；100 Action 整批执行约 10.28 秒，current-view 整批约 5.71 秒。不是单个 Action 延迟，也不是生产 SLA、持续运行或并发容量认证。
- 第一轮仓库回归因明确发现新增目录身份约束与既有 portable 恢复的兼容冲突主动停止（退出 130），不作为完整结果。修复后再构建并进行最终一轮；不并行重启全仓回归。
- 浏览器尝试使用云端本地 Chromium，进程在加载产品页面前因 socket 权限错误退出；已停止测试，不绕过限制。浏览器功能验收未完成。
- 当前测试环境的临时目录存在预置只读 Git 元数据，影响部分非 Git 项目 fixture；申请独立目录的正规执行环境启动也失败，未修改保护目录。Eval 锁定 Python 环境缺失；最终仓库回归排除会清空离线变量并触发依赖下载的 `eval-static-collect.integration.test.ts`，其余运行保留离线限制。跨语言正向断言因此失败、异常被捕获后的负向通过及自动跳过均不能算真实 Python 验收。

## 发布与规模边界

- 同工作区范围协调不是整机或分布式锁。不同项目不应将写入范围指向同一外部目录；需要独立工作区或更高层调度。
- 热路径仍有应用目录枚举和活跃 holder 校验成本；旧索引首次初始化、显式审计及成员清单更新不承诺常数成本。
- 真实模型效果、原生 Windows/macOS 宿主行为和生产持续运行需独立验收。Linux 故障注入或模拟 Docker 清理不能证明这些场景已通过。
- 正式发布应同时具备核心回归、完整可解释的发布验收和明确的部署范围。未完成项保留为发布限制，不以“已推送”替代稳定性结论。
