# 核心恢复修复验证（2026-10-21）

比较基线：`2c52b68104d35f9b8c80905c92a4fb0ce87516e5`（050）。本次修改不提升已处于开发阶段的 0.5.0 版本；master 和最新发布 tag 均为 0.4.5。

## 交付内容

1. Native 新检查登记后、child 身份登记前中断：增加绑定原 claim 与完整执行快照的停止证明，Doctor 恢复和取消可以完成；owner 未知/仍活跃或没有真实停止证明时仍阻塞。
2. Classic 自定义扩展归档：保存归档前文档证据，只接受原领取绑定的目录搬迁和确定性注记；冷恢复不重放 Archive，重复注记和成功后的恢复保持幂等。
3. Classic 检查超时：不再丢弃进程树停止确认失败。unknown 阻止受治理源码写入；恢复诊断给出原领取绑定的取消模板，真实停止后才释放。不能把已执行命令伪装成未执行重试。
4. 取消与终态停止确认统一验证精确领取身份及真实证据，空白或整串模板占位符不能作为停止证明。
5. Dashboard 完整发现与失败来源重试分离，坏归档不再冻结新运行发现；失败重试退避，来源删除可正常被观察。
6. Eval 报告读取器有界轮换，超限报告明确诊断并跳过，不能耗尽全局槽阻塞健康报告。超限仍影响证据完整性，不能视为评估通过。
7. Eval 启动记录区分 pending/dispatched；未派发中断可在启动锁内安全协调。历史/派发后 ownerless 记录须明确确认停止并绑定原字节摘要后恢复，保留原记录备份。
8. Runtime 所有存储生命周期保留紧凑投影，完整摘要/revision/文件身份校验不变；应用包装与冻结子投影不丢失验证身份。
9. Any 无 ID 恢复先限制应用，排除已验证封存历史；未提交注册保留 aborted 清单证明，审计、重建和健康任务自动恢复形成闭环。已发布成员丢失、未知协议或不确定正文仍拒绝。
10. 安装字符串 Hook 使用编码 argv，保留原路径且不删除附带用户命令；托管 Runtime 链接可安全重绑定，未知旧链接需要精确目标确认，实际目录始终不被替换。

## 原始复现回放

- 坏归档存在时，在下一轮真实 Dashboard collector 中可以发现新增运行；坏归档本身继续报告校验错误，不被当作有效证据。
- 两份大于 8 MiB 的报告之后，健康报告连续三轮均得到 1 个 case，不再停在“等待公平续扫”。
- 真实封存 100 Action 的 checkpoint 为 433,399 字节：修复前独立冷读约 95.5 MiB 瞬时堆增长；修复后同一保留数据的构建产物读取，历史物化数为 0。一次样本约 198 ms、1.8 MiB 堆增长，仍完整处理规范摘要数据。不同轮次内存受 GC 和共享环境影响；不能把它当成稳定峰值、泄漏证明或 SLA。
- 无 ID inspect/resume 不再读取其他应用或已封存 checkpoint 正文；同应用坏封存历史不阻塞唯一健康活跃任务。明确查看该坏历史仍须校验并报错。
- Native/Classic 使用实际进程或生产 SDK 的中断回归；Classic Archive 的 OpenSpec 部分使用仓库受控 fixture。没有将这些结果当作真实 Agent 模型或所有宿主平台验收。

## 使用边界

- 未知执行不能凭缺少 PID 推断停止；操作者须实际核对原命令及后代/容器。无真实证据继续阻塞是保护行为。
- 旧版本已清除注册意图且没有 aborted 证明的空分区，不能安全追认从未提交；应保留现场，不能自动忽略可能丢失的数据。
- 没有托管标记的旧 Runtime 链接不会被静默覆盖；错误中提供绑定当前目标的显式修复命令，先核对目标归属再执行。目标变化后原命令无效。
- Windows 进程终止和 junction 修复只有模拟/静态及跨平台代码检查，未完成原生 Windows 验收。未执行真实模型计费 Eval、真实宿主 Hook 或浏览器 UI 验收。
- 仍读取完整紧凑 checkpoint 并做完整规范摘要验证；首次索引、显式审计、库存维护和历史候选发现仍有随数据量增长的成本。不是分布式存储或无限规模认证。
