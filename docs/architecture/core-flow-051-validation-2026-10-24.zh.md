## 已复现的根因与修复

### Native：候选内容与执行环境混用

旧收据把文件内容和 PATH、TEMP、代理等进程环境放在同一个摘要中。Verifier 从不同会话提交时，即使代码未变，也可能被拒绝并反复要求刷新检查。

新收据分别保存内容与执行摘要。提交时复核候选和内容，检查复用仍核对执行环境。保留旧字段和旧收据读取：能证明完整且匹配的旧收据继续有效；不能证明时要求一次刷新，建立新收据。损坏或未知版本的新收据不能回退到旧校验。

### Native：生成输入选择与完整性

原 `**/dist`、`**/build` 会扫描依赖树，超限后的确定性摘要又可能被误当成可复用证据。已复现依赖目录中 20,001 个文件，以及敏感生成输入导致快照不完整时，旧 passed 被错误复用。

现在按项目根、检查 cwd 和项目清单确定生成目录，不再任意深度扫描依赖。Next 生产文件和 `types`、`dev/types` 保持绑定；仅排除 cache、trace、trace-build 和其他 dev 输出。Git 与非 Git 选择一致，生产路由中的 `logs` 等目录也不被普通源码排除规则误删。

检查开始和结束的快照都必须完整。超限、敏感文件、不安全链接或不稳定读取会给出原因，不复用旧通过结果。开始到结束之间的源码变化不能被结束摘要吸收；正常生成产物写入不视为源码修改。已完成但不能用于验收的检查保留原日志和副作用，通过原有停止核对及批准修复流程回到 Build，不自动重复执行一次性检查。

复核期间另用构建后的代码验证了 `.next/server/app/page.js` 改动：仅绑定 types 的中间实现摘要不变，最终实现的内容摘要与执行摘要均变化。未保留该中间实现。

### Classic：重开验证丢失文档证据

显式 `reopen-verification` 开始新执行链时不继承旧链输出。Full 的 Archive 因而丢失 Design、Plan 引用，可能在实际归档和 Git 提交之后才报 `Classic Archive documents are missing`。

现在只从已验收、仍有效且身份匹配的不可变 Build 证据恢复这两个文档绑定；不能跳过失效的新轮次去找更老的成功记录。归档前检查正文是否仍匹配，交付恢复再检查 Design、Plan、任务范围、原文收据和确定性归档注记。没有改变 SDK 定义、Run schema、原审批或原提交父子关系。

使用真实 `0.5.0` 自包含 Runtime 在临时项目复现归档后卡住，再仅换新 Runtime，以冷启动完成同一 Run。另验证已提交的未验收正文被拒绝，恢复原文后才允许完成；不重跑 Archive。

### Classic：可执行路径缓存错误复用

旧缓存假定进程内 PATH 不会变化。同名检查从成功程序切换到退出码 7 的程序后，Verify 仍可能复用旧成功并进入 Archive。

已删除此缓存假设，每次核对当前命令解析结果。覆盖 PATH 切换和同一路径中新安装更高优先级命令，检查仍只保存环境摘要而非敏感值。

### Dashboard：个人记忆区域的最小高度

桌面 Grid 子面板的自动最小高度被长列表撑开，父级裁切了内容和分页。只在个人记忆桌面布局解除该约束，保留工具栏、分页及面板独立滚动；未重做项目知识或窄屏布局。

## 尚未覆盖与使用边界

- 本机为 Linux、Node 24.22.1；没有真实 Windows 11 或 macOS 验收。跨平台测试分支不等于在对应系统实跑。
- Chromium 在加载页面前因 `socket() failed: Operation not permitted` 退出。没有绕过限制；不能把 CSS 检查或构建当成真实 UI 验收。
- 已安装 Vite 为 8.2.2，当前 lockfile 为 8.2.4；未修改锁文件来掩盖差异。Dashboard 构建证据以实际版本为准。
- 没有执行整仓全量测试、真实外部 OpenSpec 安装、真实模型或平台 Hook Eval、长时间负载测试。Classic 生命周期中的外部归档使用无网络进程 fixture；实际执行了本地归档和 Git 提交。
- 非 Git 工作区中的敏感文件、真正超限的生成输入或不安全链接仍可能阻塞验收。需要修复输入范围或文件状态，不能通过反复 refresh 绕过完整性要求。
- 未恢复 CI 监控，未合并 master，未创建发布或发布 npm。
