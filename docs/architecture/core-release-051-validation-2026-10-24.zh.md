## 执行过程中的失败与修正

这不是一次不间断的整仓全量测试。按登记分组执行，遇到明确失败就定位原因，保留已有报告，修正后复跑失败组并继续尚未完成组，最终逐组重新核验全部必需行为。

1. Classic 生命周期和修订测试的最小 fixture 绕过了正式初始化，或覆盖了 managed `.gitignore`，使本机锁迁移 fence 被一起提交。新交付检查正确拒绝。修正 fixture，在候选产生之前建立已有正式忽略规则，并增加强行夹带内部未知文件必须拒绝、Run 不变和交付后工作树干净的断言。没有给 Runtime 目录增加交付豁免。
2. 两个平台 Hook 测试、两个批量更新测试缺少独立项目边界，受临时目录祖先的 Git 元数据影响。为测试项目建立真实 Git 边界，保留并加强原安装/更新结果断言，没有修改生产发现规则或放宽安装身份检查。
3. 一次临时目录隔离尝试发现目标祖先仍有 Git 元数据，随即中止；它不作为通过依据，也没有删除环境已有元数据。
4. SDK 报告检查曾与测试辅助函数的正常重建重叠，因 dist 正在清理而失败。等待构建完成后重新检查通过，未把缺失构建产物当作兼容通过。

## 核心不变量

- Hook 不得越过 SDK Run 改写兼容投影；辅助行号与等价格式可以保留批准，真实要求和未复核正式注释不能自动放行。注释移动的结构位置也属于复核身份。
- 旧 050 Shape 只有摘要时，必须恢复原批准全文并匹配原指纹，才能通过 `comet native spec snapshot <change>` 保存可复验旁证；不猜测或补造原批准。Build 阶段尚无 Verify 候选时，未知正式注释仍保守拒绝并保留原 Action/claim。
- Archive 产物及其源文件逐提交绑定，不能先提交未经批准内容再删除。已提交的归档 checkpoint 保持不可变，交付后的权威收据不会让工作树重新变脏。
- 旧归档只从原 Verify、文档原文及已批准 Handoff 确定性恢复。缺少旧主 Spec 转换证据时仍保留原 Run 并拒绝，不重放 Archive。
- 明确拒绝工作流优先于“提交/继续”等词；仅提交现有代码不构成恢复授权。
- 允许目录不能通过现有或悬空软链、raw target/cwd 的链接父级路径绕过 Runtime、Git 或工作流保留根。
- Eval 的任务失败、错误身份、缺失样本/维度、畸形整数、旧报告或无效基线均不能得到发布通过凭证。
