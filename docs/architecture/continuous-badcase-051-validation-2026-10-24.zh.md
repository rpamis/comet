## 交付内容

- 根、测试与 Eval 开发规则将用户问题拆分、复现、根因、安全反例、长期登记和分层验收写入完成条件；PR 使用机器可读修复声明。
- 历史清单保持冻结，新案例进入 `config/workflow-regressions.json`。CI 核对声明来源、case ID 和比较基线，禁止静默删除行为、来源或测试映射。增量断言按文件和完整名称唯一匹配，不能由相似名称、重复同名或跳过用例顶替。
- 必要附加验收的 `pending` 状态阻止已修复声明和完整发布；确定性回归本身通过不表示浏览器、模型或平台验收通过。
- `Badcase regressions` 仍与全量测试分开。保留仅 master 的 push 触发范围，没有添加 051 直接 push 触发。PR 正文编辑也重新检查，避免沿用旧声明的结果。
- 当前发布 Eval 矩阵为 16 组：5 组当前 SDK CLI 核心场景、11 组明确标识的历史 portable 补充场景，均须通过。新增 Native blocked 后恢复及 Classic full/tweak/hotfix 完成交付场景。
- Native 会话切换前由只读 harness 捕获真实 SDK 状态、候选、检查、Wait 与会话边界，最终验证器核对恢复证据；模型 stderr 不能冒充 harness 控制记录。
- 修正旧 Classic layout 验证器对合法交付后 checkpoint 的误拒，仍通过产品校验器拒绝非法历史变化。

## 检查中发现并修正

独立复核发现，旧名称子串匹配可能用另一个通过的断言掩盖被跳过的必需用例。增量登记已改为完整身份唯一匹配，并保留反例。

增加 stderr 来源隔离时，相邻测试发现缓冲导致超时前诊断丢失；随后又发现临时 Bash 重定向无法可靠保留等待的进程 ID。最终采用流式前缀处理、显式子进程管道描述符和等待，保留无换行诊断并拒绝伪造控制记录。上述失败日志保留，修正后重新执行相邻检查得到最终结果，不将前两轮算作通过。

## 尚未证明的范围

没有执行 Docker 或真实模型 Eval，没有运行整仓全量测试，也没有启动远端 CI。当前 SDK 离线驱动的用户决定和角色执行是明确模拟，不等同于模型自主完成。新矩阵须对最终提交重新 collect、审核基线并 validate，旧矩阵通过结果不能替代。

登记器自动执行 Vitest `.test.ts`；UI、真实模型和平台 Hook 仍需对应层级的附加验收。声明是否漏报、外部证据是否真实、断言是否完整表达用户问题，仍由作者与 Reviewer 负责，不能由 JSON 存在推断。手动 CI 的默认基线是当前提交，只核对当前树；PR/master push 使用事件基线。当前版本不支持删除/迁移旧登记来绕开保留检查。
