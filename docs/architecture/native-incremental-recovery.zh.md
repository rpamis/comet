# Native 增量验证与恢复

当前协议来源：`report:2026-11-10-agent-platform-execution`；此前的内容证明撤下来源为 `report:2026-11-08-agent-managed-workflow-content`。用户确认普通开发、测试和命令由 Agent 平台工具执行，撤下 Native/Classic 受管检查、进程身份、停止握手、文件指纹、内容 hash 和自动失效机制。保留共享 SDK 请求标识、安装包摘要及 Git 提交 ID。下方历史验证记录反映当时的实现，不作为当前执行或文件证明要求。

## 编辑与检查

Agent 对照需求、实际修改和真实结果判断影响。普通文件变化不撤回批准，不自动回到 Build 或重新验收。需求或授权有实质变化时，请求受影响的用户决定；实现需要修复时，通过原 Runtime 修订候选。

Agent 在平台工具中执行检查，保留命令、工作目录、真实结果和日志引用，再向原 Action 提交报告。是否复用已有结果由 Agent 判断；Comet 不运行检查、生成进程收据或核对日志内容。最新真实失败不能被更早的成功覆盖，一次性命令和未知执行不能自动重放。

Verifier 覆盖当前候选全部验收项。原检查可复用不表示验收已完成，待用户接受的结果继续等待用户决定。用户选择的执行方式、TDD、审查及独立会话要求继续有效。`edit-review observe/record`、输入快照和保留检查证明协议已撤下；由原 workflow 的业务继续和修订入口处理。

## 归档与恢复

归档沿用原 Run、用户决定和事务。完成的步骤按记录继续，不因当前材料变化重置进度或重写 Specs。未知结果先在原平台核对原任务和实际副作用；失败后由 Agent 明确选择修复或重试。交付仍核对批准路径、分支及实际 Git 提交，不能夹带无关文件。旧业务数据自动适配，旧执行器和进程记录不恢复。

普通业务流程不创建锁；每个 workspace / Run 单一写入者，路径检查与事务日志保留实际写入和恢复边界。普通任务的超时、取消与进程清理由 Agent 平台负责；Comet CLI 自行启动的 Eval、下载等能力保留实际清理责任。不能用文件年龄推断进程已经停止，不能把失败或未知执行描述成成功。

## 验证边界

确定性测试验证公开命令、真实检查、确认等待和事务恢复。模型是否遵循简化协议，以及真实项目是否缩短数小时归档，需要相应实测；未获明确启动请求时不执行 Eval。
