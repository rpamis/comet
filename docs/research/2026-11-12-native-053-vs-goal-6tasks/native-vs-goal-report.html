可引用的实验结果

在预先固定的 WorkBuddy Code 与 SkillsBench 各 3 道题上，使用同一 DeepSeek 配置（主模型 deepseek-flash[1M]）和 Claude Code 2.1.318，每题每组保留 3 次结果，共 36 个计分位置；另有 1 次环境中断的 Native 运行及替代记录。WorkBuddy Code v1.0 选样的 pass@3：Native 0.5.3 为 2/3（66.7%），无 Comet 的原生 Goal 为 2/3（66.7%）；SkillsBench v1.1 选样的 pass@3：Native 0.5.3 为 2/3（66.7%），无 Comet 的原生 Goal 为 3/3（100.0%）。pass@3 指 3 次尝试中至少 1 次取得原题满分。这是代表题选样结果，不代表完整官方榜单成绩。

选题与比较边界

WorkBuddy Code 与 SkillsBench 各选 easy、medium、hard 1 题，难度沿用原数据集标注。每题每组 3 次，共 6 题、36 个计分位置。另有 1 次因环境中断而被替代的 Native 运行，真实模型运行合计37次，原记录及额外消耗保留。用户在首个真实模型输出前将旧 16 题范围缩减为本轮六题；固定选题后不因成绩换题，不自动增加有效结果轮次。

模型执行使用内置 comet eval，两组保持原题与原评分器，不额外注入领域 Skills。Native 使用启动前冻结的 0.5.3 编译包；运行期间合入的 00956d7c（移除文件大小限制）不在本轮候选中。两个运行容器内 CLI 均返回 0.5.3，841 个 CLI、编译代码及资产文件与冻结包一致。Goal 不安装 Comet。主模型 deepseek-flash[1M]，两组 Haiku 路由都固定到主模型，其余 DeepSeek 路由一致。每个 Run 使用 1 个 worker，总模型并发上限 4；按镜像就绪与空余并发位分批执行，保留实际启动时序。后续环境构建启用无固定总时限选项；模型仍受固定计划中的逐题执行预算约束，例如 SkillsBench 高难题为 3600 秒，不能将本轮描述为模型完全不限时。原评分预算不变。

旧 Goal Run 执行期间评估器构建辅助代码发生修改，原始报告因此拒绝评分。保留这些原始失败记录和模型输出，将候选原样保存，并在精确匹配原固定计划校验值的冻结适配器中调用同一内置评分器补评分。补评分不调用模型、不修改候选；存在参考材料访问或评分错误时仍不能计为成功。环境准备的改动不涉及原题、Agent交互或评分规则。

原批次的本地 Skill 脚本副本来自共享工作区；缓存题第3次曾用grep读取其中的Spec路径代码，未执行这些脚本，保存的14个脚本与冻结CLI资产不同。实际CLI执行被冻结，但不能声称所有可读上下文文件都逐字一致；此限制不作为删除有效低分的理由，详见实验计划。

这是六题小样本选样，不代表完整官方榜单。环境准备不计入模型耗时。效率与 Token 为可观测范围，不能当作完整工作流账单或无混杂因素的因果效果。官网引用必须同时给出模型、题数、重复次数与完整成功定义。
