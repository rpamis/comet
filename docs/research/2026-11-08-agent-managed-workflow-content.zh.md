# Native / Classic 移除内容证明机制

来源：`report:2026-11-08-agent-managed-workflow-content`。比较基线：`5426c4cbb3569e749ce8050888517f93b8437f5d`，分支 `053`，版本 `0.5.3`。

## 已确认范围

用户要求删除 Native 与 Classic 的内容指纹和 hash，让 Agent 判断编辑影响和验证范围。用户随后确认保留共享 SDK 的 Action 请求标识、安装包摘要及 Git 提交 ID。本次不修改网站。

移除的机制包括项目文件输入指纹、实现候选内容绑定、正式文档内容摘要、检查日志内容证明，以及由这些内容证明触发的自动失效、强制编辑判断和重新验收。不得仅关闭校验、换一个名称保存同一证明链，或把内容 hash 换成时间戳后继续自动作废。

Agent 对照需求、实际文件与执行结果，决定继续原步骤、补充检查、修订实现或重新确认需求。Runtime 记录当前 Run、步骤、执行者、命令、退出状态、日志路径、用户决定和归档进度；它不再从文件字节变化推断验收是否适用。

## 保留的职责

- 原 Action 的领取、结果和中断恢复；真实失败或未知执行不能伪装成成功。
- 用户明确要求的确认、独立验收与授权范围。需求修订仍通过正式入口提出，由 Agent 说明实际变化。
- 检查计划、工作目录、超时、进程停止和原执行来源。复用由 Agent 选择，不再要求完整项目指纹或逐文件保留证明。
- 归档事务、已完成写入及重试进度。恢复不重复已完成的副作用。
- 路径隔离、文件类型和工作区归属检查。Git 提交 ID 继续用于真实的分支、合并和交付操作。
- 共享 SDK 自身的请求绑定、CAS revision 和存储格式；包分发摘要不属于本次移除范围。

## 内容证明案例迁移

本次沿原 ID 迁移 97 项增量登记和 9 项历史登记。冻结历史文件不修改，历史迁移通过 historicalTestMigrations 关联；已经存在的独立迁移保持原文，仅在后续确实撤下其替代协议时追加 supersededBy。旧 bugfree 移除和丢失本机 overlay 后接收原 Verifier 失败等未受影响的迁移继续执行原契约。

审计文件保存原登记、完整旧测试正文、逐案例选择器、保留行为映射和源码差异。原内容证明声明经过两轴复审后撤下；只删除属于本次迁移且不再被有效登记、核心回归或替代契约引用的声明，共 113 处声明、162 个生成案例。共享声明只要仍含有效变体便保留。证据摘要用于既有测试迁移审计，不参与产品执行；没有把文件证明换成时间戳或另一种内容证明。

保留行为单独验证，包括首次检查失败不重放、不提前推进；真实 prelaunch 中断后的原命令恢复与损坏 SDK 绑定拒绝；Git 补查失败、修复后只重跑 A 而保留一次性 B；full 补查恢复保留 Design/Plan 与批准且不重放 Build；已搬迁归档和游标写入中断的原事务恢复；父目录别名及短路径下的公开执行与交付。

测试入口按文件合并相同选择器，保留所有来源 case ID 和原 registered-ID 别名。Windows 专用整树终止组继续单独归属 Windows，没有合入 Linux 分组。迁移链中曾撤下功能后，后续移动测试不会重新允许声明原功能问题已修复。

## 兼容性说明

共享 SDK 的请求、存储和检查点标识继续保留。Classic 旧 SDK 定义中的少量 `contentHash`、`handoffHash` 字段承载原 Action 请求标识，不再读取文件计算内容证明；保留旧定义以便原 Run 继续。Native/Classic 新检查结果不写入文件或日志摘要。

归档保留原操作声明、路径范围和已完成进度；文件内容不再作为自动重验条件。传输包完整性、安装包摘要及 Git 提交身份继续用于对应传输、安装和 Git 操作，不用于决定 Build/Verify 是否失效。本改动位于 053 工作区，尚未提交、推送或发布，不能描述为已发布到 0.5.2。
