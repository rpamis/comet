# Comet 与 Agent 平台的记忆机制对比

日期：2026-11-02。范围：当前 `052` 工作区的个人记忆、项目知识及其中的项目记忆文件层，与 Claude Code、Codex、智谱 ZCode 的官方公开机制对照。本记录是设计分析，没有修改产品行为，也没有运行真实模型、效果或性能对比实验。

## 结论与比较边界

Comet 已有文件存储、检索、按需展开、预算控制、增量交付、来源校验和学习收尾等完整基础。主要可用性差距在于 Agent 平台掌握会话生命周期，可以自动把短索引放入新会话、在合适时机维护记忆；Comet 的完整入口仍需要执行任务包中的 `contextRequest` 或 `comet task`。功能存在不等于每个接收 Agent 都已执行它。

具体例子是 [task-context.ts](../../domains/workflow-contract/task-context.ts)：它构造接收方需要再次执行的命令，并保留任务和会话占位值。这为跨平台提供了统一入口，同时也增加了一次 Agent 组装参数、调用命令的机会。可优先将适配层已知的身份与上下文交付自动接起来。

这是对接入路径和操作负担的判断，不能据此断言某产品记忆“更准确”、减少了多少 token，或领先多少版本。平台公开文档通常没有披露全部召回、压缩、排序实现，不能推断它们都采用向量数据库或具体模型。

| ----------------------- | ---------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------- |

来源：[Claude Code Memory](https://code.claude.com/docs/en/memory)、[Codex Memories](https://learn.chatgpt.com/docs/customization/memories)、[ZCode Memory](https://zcode.z.ai/cn/docs/memory)、[ZCode Wiki](https://zcode.z.ai/cn/docs/repo-wiki)。

Claude Code 文档明确将指令文件与 auto memory 视为上下文，而不是强制执行配置。它和 ZCode 都刻意避免重复保存能直接从代码或 Git 读取的事实。ZCode Wiki 是项目导读能力；公开文档没有证明它会像 Comet 一样，在每次任务中统一排序、预算化交付全部项目知识，不能把两者视为相同实现。

## Comet 已有能力，不能重复当作新功能设计

| 展示使用证据       | [插件桥](../../domains/comet-plugin/integration.ts) 区分候选、全文/摘要交付、应用及实际反馈；项目记忆索引不当作有效命中重复计数                                          | 有候选、已交付、被采用、真正有帮助仍是不同层次；没有反馈不能补成成功      |

## 优先优化建议

### 先提高“能看到”和“少操作”

1. **沿用当前 ContextDirector 生成一个短、稳定、带来源的接入包。** 核心偏好和当前项目索引在支持的会话/回合入口自动交付；正文继续按需读取。没有这些事件的平台保留一次启动入口，并明确显示是否已接入。不要再增加每次写文件都必须检索的协议。
2. **让 Agent 只记住读取、展开、提交学习三个职责。** 底层继续复用 comet task、expand-context 和现有学习文件。由适配层携带项目、阶段、会话和应用标识；Agent 写实际业务内容，避免记忆插件暴露更多机械字段。
3. **生成适合标准文件工具读取的只读投影。** 文件中保留类型、适用条件、简短结论、来源和更新时间，展开地址稳定。直接读取可降低命令调用摩擦；来源变化由当前 Runtime 校验或明确标注，不把投影升级为新的事实权威。

### 再提高“记住什么”和“以后能找到”

4. **利用已有学习事件做后台整理，不把整理放在核心推进路径。** 显式记住/忘记及时执行；自动观察先记录候选，在空闲时去重、合并和评审。当前学习队列、评审和 task-learning 已存在，应接到合适的生命周期，而不是新建另一条学习管线。任务或测试成功不能自动替所有已交付条目生成“成功使用”反馈。
5. **把“用户偏好”“已验证项目经验”“当前代码事实”分开更新。** 偏好以用户纠正为主，项目经验保存适用前提和来源，代码事实可以从当前文件重建。索引中过期条目标记原因并提供更新入口，避免常驻文本越来越长。
6. **对平台内置记忆保持明确分工。** Comet 可作为跨平台的可追溯知识来源；平台自己的 auto memory 继续保留平台内会话经验。避免把同一长文本同时写入 AGENTS.md、平台 auto memory 和 Comet 索引；也不要直接改 Codex 等工具的生成状态文件来伪装接入。

### 用行为验证，不靠命中率证明价值

先做不调用真实模型的接入验证：新会话和子 Agent 是否实际收到正确索引；来源更新后是否避免交付旧正文；连续请求是否去重；插件失败能否继续任务。效果层应比较同任务下的重复纠正、漏用约束、错误使用陈旧知识、额外命令/延迟与 token 成本。真实模型评估必须另获用户明确启动请求，不能自行启动或重跑。
