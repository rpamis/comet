# bugfree 模型对照准备

> 历史记录：该模式已于 2026-11-05 撤下。当前状态、失败根因和证据索引见[撤下记录](2026-11-05-bugfree-retirement.zh.md)。文中的启用步骤和待办不再适用于当前产品。

本文件准备未来的模型对照，不授予执行权限。当前未启动 Eval，也没有模型正确率、墙钟耗时或 token 对照结果。公开入口为 `comet eval`；启动前仍须用户明确指定场景、样本和轮次。普通状态机测试和当前任务的独立代码验收不计入这些模型样本。

## 固定候选

计划比较 24 个候选，每种模式每个候选 3 次，共 144 次。可重放项目、文件 SHA-256、无外部依赖的锁文件和隐藏判定已保存在 `test/fixtures/native-bugfree-eval/frozen.json`。以下表格用于定位案例；实际模型运行前仍须独立人工复核，登记最终快照摘要，并确认执行环境和授权范围。这组小型案例用于覆盖设计边界，不代表生产项目的完整难度分布。

每对保留同一需求、初始系统和依赖，只改变最终候选的正确性。参与 Verify 的 Agent 只看到需求、候选及本模式的真实交接；不得看到下表缺陷说明、标签或隐藏判定。

| 正确/缺陷 ID | 要求                                               | 缺陷候选的唯一差异                   | 独立隐藏判定                                             |
| ------------ | -------------------------------------------------- | ------------------------------------ | -------------------------------------------------------- |
| F01 / F02    | 把闭区间内的库存数量求和，包含两端                 | 排除上界                             | 对空区间、单点和三点区间核对总量                         |
| F03 / F04    | 仅在已支付且未撤销时发货                           | 把且改为或                           | 穷举支付与撤销两种布尔状态                               |
| F05 / F06    | 上游金额以分传递，下游按元展示                     | 下游再次乘以 100                     | 从接口输入到最终文本，核对 12345 对应 123.45             |
| F07 / F08    | 两个入口共用同一折扣规则                           | 第二入口沿用旧费率                   | 相同订单通过两个公开入口得到相同结果                     |
| F09 / F10    | 已取消任务不再进入执行态                           | 取消态仍允许 start                   | 经公开状态转换入口取消后启动，断言无执行副作用           |
| F11 / F12    | 重启恢复已完成写入，不重复追加                     | 恢复再次执行已完成追加               | 在持久化完成点中断并重启，断言文件恰有一次记录           |

| F15 / F16    | 项目内相对路径在 Windows 和 POSIX 同义             | 仅用正斜杠字符串前缀判断边界         | 临时目录中的合法路径与相邻目录逃逸分别核对               |
| F17 / F18    | CLI 的显式 false 保持 false                        | 使用布尔真值强制转换字符串           | 在公开 CLI 传入 false，检查退出码、JSON 与实际副作用     |
| F19 / F20    | 按钮只提交一次，完成后可再次提交                   | 请求期间按钮仍触发重复提交           | 浏览器快速双击并观察网络次数，完成后再次点击             |
| F21 / F22    | 必须通过用户指定的配置检查后才能接受               | 候选只输出“检查通过”，实际配置仍无效 | 使用冻结的必需命令，核对命令退出码和配置内容             |
| F23 / F24    | Supervisor 的两个合法 Child 合并后保留唯一任务编号 | 父级集成覆盖编号分配器               | 经父级公开入口创建两个任务，断言持久化编号不同且都可读取 |

每个候选冻结记录须包含：ID、需求文本摘要、完整项目快照 SHA-256、依赖锁文件 SHA-256、可重放的环境、正确性标签、人工复核引用、隐藏判定代码及预期结果、目标 Runtime/Skill 版本。正确与缺陷候选都要先运行隐藏判定。无法确定真值的候选在开始比较前替换并留理由；看到模型结果后不删除困难样本。

## 完整流程

另准备 C01 首轮通过、C02 一次修复、C03 多次修复、C04 补查、C05 阻塞后恢复、C06 Supervisor 父级修复六个任务，每种模式每个任务 3 次，共 36 次。执行真实 Build、Verify、修复和报告，用户决定采用冻结的模拟策略并明确标注，不能冒充真实用户批准。

完整流程需预先固定初始项目、需求、允许的环境恢复动作及最终隐藏判定；不固定模型必须选择的诊断命令。全部修复轮计入累计 Verify 与返工成本，不能只选最后成功的一轮。

时序取自 SDK Action 与平台任务真实事件；token、缓存和费用取平台调用记录，汇总主 Agent 与所有 Subagent。已计入 total 的 reasoning 不重复累加。无法采集完整 token 时报告覆盖率，不以字符估算替代。基线捕获的额外成本单列，并保留端到端用户墙钟指标。

standard 与 bugfree 使用相同等级模型、环境和需求，顺序交错。blocked、超时、依赖故障、未完成均保留；材料完整的固定候选上，它们不算正确判定。分位数使用 nearest-rank。只有双方均完成且判定正确的成对样本进入性能比较，其余仍进入质量、完成率和失败报告。

先比较正确率、漏检、误报、完成率和返工：bugfree 不低于 standard，漏检、误报及误报引起的返工不增加。再检查耗时中位数 ≤50%、P90 ≤70%，总 token 中位数与总和 ≤50% 的目标。按类别和必需检查占主导的任务单独报告，同时保留总结果与全部变化案例。有限样本不构成对未来任务正确率的保证。

## 执行前检查点

1. 用户明确授权实际 case ID、样本和轮次；本计划建议的 180 次不自动构成授权。
2. 完成上述项目与隐藏判定冻结，并确认隐藏材料不会交给参与 Verify 的模型。
3. 使用公开 `comet eval` 目标与已安装执行器完成装配；先确认其记录能提供所需指标。缺失采集能力时先补普通代码和确定性测试，不能私下调用模型补数据。
4. 固定协议、模型、平台、环境与失败处理，再执行授权子集。不因失败补跑新轮次，除非用户另行要求。
5. 保存原始结果、排除原因和采集缺口。没有数据时保持“未执行”；未达到质量条件时不宣布性能目标完成。

## 已完成的离线准备

首批单文件函数种子未满足实际类别要求，第二轮独立验收已判 A36 失败。现已按下表要求补齐实际边界，旧失败结果保留：跨模块使用三个独立模块；持久化用两个独立 Node 进程及磁盘完成记录，首进程在完成点以 73 退出；CLI 核对真实退出码、stdout JSON 和落盘配置；UI 用真实 Chrome/Edge、DOM 点击及本地 HTTP 请求；必需命令实际执行；Supervisor 由真实 SDK、Git worktree、Child 检查与集成生成父级候选，再在父级提交正确或缺陷代码。隐藏判定在字节一致的隔离副本运行，避免改变已绑定候选。具体重放条件及控制器入口见 test/fixtures/native-bugfree-eval/README.md。

`test/helpers/native-bugfree-benchmark.ts` 从冻结材料重建临时项目，将隐藏标签、判定代码及参考修复留在参与评估的工作区之外。它为 24 个候选和 6 个流程起点装配公开 Eval manifest。manifest 只检查结果文件的格式，质量结论由外部隐藏判定和 `scoreFrozenBugfreeVerdict` 单独计算；格式检查通过不等于候选正确。

`test/domains/eval/native-bugfree-preparation.test.ts` 已完成以下普通确定性检查：逐文件及判定代码摘要一致；12 个正确候选通过、12 个缺陷候选失败；6 个流程的起点与参考修复符合预期；两个父级候选具备真实生成的 Child/集成收据，最终父级零命令路径也可完成候选绑定；公开 `comet eval --collect` 在离线环境中收集全部 30 个工作区；同一缺陷父级也已按 standard 建立真实 Run，保留父级语法检查而不把它当作语义通过；任务描述没有携带隐藏标签。`frozenBugfreeMetrics` 对接现有 Eval 事件字段 `input_tokens`、`output_tokens`、`total_tokens`、缓存和费用统计，缺失值保留 null，reasoning 不重复加入 total。

流程起点用于准备完整修复任务，参考终点只供独立判定，不交给模型。C03 包含两个独立问题；C05 提供环境缺失与模拟操作员恢复约定；C06 明确要求真实 Supervisor Child 和集成记录。实际运行必须根据模型行为记录覆盖到的路径，不能为了凑多轮修复强迫失败，也不能把这些静态种子当作真实 Runtime 收据。时序数据从实际执行器取得，再传给指标映射；当前没有实测计时或 token。

实际 Supervisor 控制器支持两种模式，返回原控制项目、集成工作区和当前 Runtime 任务包。模型任务开始前须在选定执行工作进程内调用该准备函数；不复制另一台机器的 Run。公开 manifest 保留这个控制器前置条件，静态收集只验证目标装配。

本轮完成的是材料、隐藏判定、指标映射和公开入口的离线装配验证，没有调用模型、启动容器或完成模型对照。模型执行环境、最终人工复核和用户指定的运行范围仍须在启动前核对。未采集的数据保持缺失，后续授权只覆盖用户明确指定的场景、样本和轮次。
