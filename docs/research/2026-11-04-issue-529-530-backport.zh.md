## 实际行为与修正

### 文件锁释放

协调器释放失败时，只尝试移除身份和内容仍匹配本次持有记录的锁。其他持有者、元数据变化和检查失败分别报告，保留不能安全删除的记录。恢复协调器后，同进程能够再次申请已成功释放的锁。

移植后的 Windows 夹具使用 junction 代替需要额外权限的目录符号链接，仍断言无法安全检查父目录时保留锁。Changelog 只描述上述释放补救及诊断，不承诺所有状态写入超时都已消除。

#529 的完整重入、释放失败向上层传播和 Action 恢复协议仍未解决；原报告的 macOS 多次状态写入场景未在本轮复现。不得将这次交付描述为整个 #529 已关闭。

### Classic 归档交付

在读取原有归档清单时，从已绑定摘要的 `optionalFiles` 派生活动路径的删除许可，不改写历史清单或重新执行 Archive。提交范围删除了已跟踪栅栏时，必须提交内容匹配的归档副本；未跟踪的临时栅栏保持可选。

`.comet-state.lock` 和 `.comet-state-transaction.json` 两处来源均覆盖正常搬迁、归档副本缺失和内容变化。正反案例均通过实际命令 bundle 执行；原有夹带路径拒绝、归档历史和跨 worktree 查询断言保留。登记保留原 report 来源并补上真实 Issue 链接，测试选择器限定这两种路径。

### watchdog 测试收尾

PR #536 的 Node 22 CI 曾在 `eval-stop-watchdog.test.ts` 清理目录时发生 `ENOTEMPTY`。该测试观察到 `interrupted` 和 owner 退出后，后台停止操作仍可能在释放管理记录的文件锁。

本轮在 WSL Linux 中控制 `dashboard-run.json.lock.*.removed` 的 unlink 时序：终态已可见时阻塞释放，旧测试的“释放已完成”探针失败；在原终态及进程退出断言之后等待 `requestStopEvalRun` 收尾，同一探针通过。正式改动只保留这次等待及说明，未保留注入或延迟，也未改动产品停止逻辑。若原操作已结束，该入口可能进行一次幂等清理；这些操作仅作用于临时测试夹具。

这属于测试夹具收尾修正，不新增用户行为修复声明，也没有启动真实模型或评估场景。
