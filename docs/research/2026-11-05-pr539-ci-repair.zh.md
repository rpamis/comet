## 已确认的问题与修复

| 独立行为                                           | 根因和处理                                                               | 回归登记                                                                                           |
| -------------------------------------------------- | ------------------------------------------------------------------------ | -------------------------------------------------------------------------------------------------- |
| Classic SDK 交接读取到过期的派生状态               | 交接沿用 SDK Run 的权威输入；只有原始摘要匹配时才恢复缺失的派生 manifest | `classic-sdk-authoritative-handoff-sources`、`classic-sdk-recover-original-input-manifest`         |
| Classic 重用检查仍重复读取大量文件                 | 在同一次观察中传递已验证的 Run 和输入，不重复读取投影                    | `classic-sdk-reuse-read-overhead`                                                                  |
| 中断的 Classic 检查丢失原计划                      | 查找原始已启动检查时越过已验证的未执行记录，保留 Action 绑定校验         | `classic-ci539-interrupted-check-plan`                                                             |
| 混合编辑由文档目标提前决定为无行为变化             | 检查每一个目标；未判断的实现修改仍留在 Verify 等待 Agent 判断            | `native-ci539-mixed-write-review`                                                                  |
| 检查执行后仍绑定执行前的输入                       | 提交实际执行后的原始快照；不完整输入不能借旧快照通过                     | `native-ci539-executed-input-binding`                                                              |
| 只读实现修订领取后退出，或返回结果被拒绝，无法继续 | 重新观察原只读 Action，沿用原 claim 完成；不执行原 Archive 写入          | `native-ci539-readonly-revision-recovery`                                                          |
| 后续正式材料编辑被已完成的旧复核阻塞               | 作废已被当前文件替换的旧提案，当前内容仍须取得新的复核结果               | `native-ci539-applied-review-supersession`                                                         |
| 本机 overlay 丢失后无法记录原 Verifier 失败        | 只记录原任务失败，保留本机证据缺失状态，不重建空检查记录                 | `native-ci539-lost-overlay-verifier-result`                                                        |
| Portable Archive 写入后的游标与恢复输入不匹配      | 沿用原事务证据，仅对明确归属本次事务的路径更新输入绑定                   | `native-portable-archive-written-cursor-recovery`、`native-portable-delta-rebase-input-binding`    |
| Supervisor 在错误工作区验证或过早清理集成工作区    | 将验证绑定实际集成工作区，完成最后输入检查后再清理                       | `native-supervisor-recovery-execution-workspace`、`native-supervisor-archive-check-before-cleanup` |
| 不可重复检查仍出现不可执行的重试选项               | 根据当前候选的重复执行能力提供决定，保留原执行和恢复证据                 | `native-one-shot-retry-capability`                                                                 |

完整来源、预期、禁止结果和精确测试选择器见 `config/workflow-regressions.json`。上述登记均追加，未删除历史登记或降低历史安全断言。

## 契约与测试迁移

- 默认 v3 的高层入口可在同一次请求中推进已授权内部步骤；v1 兼容测试通过真实公开 start 入口创建 v1 Run，继续验证旧的逐 Action 协议。Supervisor 和固定应用保留其交接边界。
- 严格文档策略用显式 `document_writes: revert` 或 `document_evidence: strict` 测试。普通编辑不再依赖文件扩展名、AST 或命令白名单来推断语义；由当前 Agent 判断实际差异。
- 旧版收据 fixture 通过真实旧算法采集输入摘要，移除当时不存在的新字段，避免制造混合格式。生产校验继续拒绝不匹配的收据。
- 正式材料的无行为变化复核已通过后，允许继续 Archive。保留用户文件、原批准和最终归档内容断言，不再要求额外回 Build。
- Rule、Native/Classic Hook、双语 Skill、共享引用和发布资产契约同步；产品修改位于源码与发布资产，本地安装副本不作为源码提交。
