# Runtime PID 退役与测试迁移

授权来源：`report:2026-11-09-runtime-pid-removal`。用户要求实施此前六项减负，并明确提出“pid 可以完全移除”。本轮撤下流程锁、检查记录及恢复判断中的 PID、进程创建身份、跨机器存活推断、年龄接管和旧协调票据；操作系统停止当前执行器持有的 ChildProcess 仍保留。

## 保留的行为

| 撤下的机制                                | 当前行为与替代验证                                                                                                                                           |
| ----------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| 记录 PID 后反复探测、等待旧 owner 过期    | 复用现有 SQLite 事务互斥；连接关闭或进程退出释放锁。真实子进程退出、独立进程并发写入及 Native 恢复排他分别验证。                                             |
| 原协调器票据、跨机器 PID 及同字节替换指纹 | UUID 标识本次操作，保留其他 owner 的记录；旧格式首次退役需明确确认实际操作停止，真实仍持有事务时不能接管。                                                   |
| PID 死亡后自动把未完成检查认作孤儿        | 沿用原 Run、检查结果和日志。没有完成结果时保持未知，Agent 核对实际副作用并明确提交停止事实后，才开放原范围的显式重试。一次性检查和外部 Verifier 不自动重放。 |
| 恢复方按历史 PID 杀检查树                 | 原执行器监听停止请求，并用自己持有的命令句柄停止执行。停止请求本身不算停止成功；旧已确认的停止收据继续有效。                                                 |
| 新 Classic Run 的普通受管检查与收据回合   | v2 Run 接受平台检查报告。失败报告在领取前拒绝；空检查说明原因。旧 v1 Run 和固定应用继续原定义。                                                              |

移除 PID 不能把执行到一半的 Git、文件发布或外部命令变成已完成。明确未知、保存真实失败和防止重复副作用仍是恢复要求。

## 原记录与覆盖去向

[原登记](2026-11-09-runtime-pid-retirement/registry.json)、[完整旧测试正文](2026-11-09-runtime-pid-retirement/tests.json)、[逐案例映射](2026-11-09-runtime-pid-retirement/mapping.json)和[测试差异](2026-11-09-runtime-pid-retirement/tests.patch)共同保存迁移。原测试正文取自 `7f016b28`，没有把当前修改后的文件当作原断言。[退休及替代名称](2026-11-09-runtime-pid-retirement/retired-tests.json)区分删除策略、改名和旧版本夹具。

原 `config/workflow-regressions.json` 字段与既有迁移链保持不变；本轮在末尾追加 `testMigration` 或 `supersededBy`。`feature-removed` 表示原机制已撤下，不声明旧 PID/年龄策略仍通过；`tests-moved` 保留原业务要求，以当前执行边界继续验证。审计资料的摘要沿用已有登记器的不可变证据要求，不进入 Runtime 或项目配置。

四个名称替代需单独核对：

- 跨机器 owner 阻止迁移，改为停止后不依赖机器/PID 恢复迁移。
- 进程身份查询期间取消，改为监管器未就绪时取消，继续验证未启动、无晚到启动。
- 自动推断孤儿并保存中断，改为保存 Agent 明确确认的原操作中断，再显式重试。
- 真实 owner 退出后的 PID 证明恢复，改为测试观察真实命令退出、提交原操作停止事实，并验证只在显式重试时执行第二次。

Portable 与 Supervisor 夹具改用命令实例 ID。保留未知不得重放、失败不能通过、旧停止事实不可转给另一检查、部分恢复可重入和实际命令停止的断言。当前线程、机器名或 PID 不再决定恢复权限。

## Classic 新旧 Run 的范围

六个既有 SDK 夹具明确固定原 v1 工厂，继续覆盖受管检查、旧恢复及升级。generated 用例仅用该工厂初始化未执行的历史 Run，后续操作继续调用当前生成 Runtime。没有把 v2 新 Run 提交旧检查计划导致的失败描述为 v1 不兼容。

v2 的默认初始化、full/hotfix/tweak、失败检查拒绝、完整验收、批准、归档、一次归档、Git 交付和无关文件保护由独立 source/generated 用例覆盖。新旧定义分别编译；固定应用的工厂没有改成 v2。

## 验证边界

最终结果汇总在实施文档及验证数据中。失败轮次保留，只有修正明确原因后的实际成功运行计为通过。普通确定性测试、生成 Runtime、真实平台 Hook 和模型 Eval 分别报告；本轮没有启动 Eval，也没有把定向检查写成仓库全量或真实平台验收。
