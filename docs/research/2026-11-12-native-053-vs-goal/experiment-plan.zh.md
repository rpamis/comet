# Native 0.5.3 与 Goal：16 题 pass@3 对照

用户授权：从 WorkBuddy Bench 和 SkillsBench 合计选择 16 题，比较 Native 0.5.3 与不使用 Comet 的 Claude Code 原生 Goal；每题每组独立执行 3 次，共 96 个模型样本。两组均使用已授权的 DeepSeek 配置，产出可供官网引用的 HTML 报告。本任务只生成报告，不自动发布网站。

## 运行前固定的选题方法

选题只读取上游公开元数据、原题、当前适配支持状态和历史调试题登记，不读取隐藏答案或观察本轮模型成绩。清单保存在 `selection.json`，运行后不因为低分替换题目或扩大轮次。

- WorkBuddy 使用当前已接入的 Code v1.0 子集，选 8 题，覆盖缺陷修复、新功能、重构、资源可靠性、数据报表、API 契约、安全加固和产品分析。难度配额为 2 easy、3 medium、3 hard。
- SkillsBench 使用 v1.1，8 个领域各选 1 题：网络安全、金融经济、工业物理系统、数学与形式推理、媒体制作、自然科学、办公和软件工程。难度配额为 1 easy、4 medium、3 hard。
- 各层内将可用题目 ID 排序，再用 Python `random.Random(20261112).choice` 选取；每个数据集独立使用同一种子。候选池随清单保留。
- 排除曾参与调试的 `bug_fix-easy-a_crash_in_local` 和 `dialogue-parser`。只从两组均能执行的任务中选择；不支持的工作目录、网络要求或评分契约不静默放宽。

这是覆盖任务类型的 16 题选样，不声称是两个完整数据集的无偏随机总体估计或官方榜单复现。官网引用必须保留数据集、题数、重复次数、模型和评估方式。

## 两组条件

使用当前 `053` 的产品代码和固定 Claude Code 2.1.318。两组读取完全相同的原题、初始业务环境和上游评分器，不注入数据集附带的领域 Skills；隐藏评分仅在模型执行结束后的候选副本中进行，不向执行 Agent 回馈隐藏测试或参考答案。

Native 通过当前 Native Skill 和公开 CLI 完成自身流程；Goal 通过 Claude Code 原生 `/goal` 执行，容器不安装 Comet CLI、Skill 或 Runtime。Goal 不可用时标为执行失败，不降级成普通提示词。Native 的流程检查单列，不要求 Goal 产生 Native 状态。Goal 的完成判断方式见 [Claude Code 官方说明](https://code.claude.com/docs/en/goal)。

模型参数与路由见 `model-config.json`。主模型为 `deepseek-flash[1M]`。既有 Goal 执行器要求 Haiku 路由使用主模型，因此本实验的 Native 和 Goal 都采用这一设置；其他 DeepSeek 路由保持一致。实际模型标签原样保留，不声称所有内部调用只使用一个模型标签。

两组均使用既有模拟用户政策、最多 40 次外层交互，不限制整个样本的总时长；上游评分器时限和任务资源要求保持不变。每次尝试使用新的隔离工作区与会话，Native 内部修复或 Goal 自身续行仍属于同一次尝试。计划同时启动两个数据集的两组，各 1 个执行器，总并发 4，减少执行时段差异。

## 预先确定的评分口径

主指标是原题完整成功的 pass@3：每题 3 次尝试中，至少一次取得上游原始 reward 1.0。分别展示两个数据集的分子与分母，各为 8 题；原始部分得分同时保留，不强行将不同数据集的数值 reward 混成一个平均分。

同时报告 pass@1（全部尝试的完整成功率）与 pass^3（同一题 3 次全部完整成功），不通过整体成功率的立方估计 pass^3。Native 流程合规和原题成功分别展示；流程完成不能替代业务成功。

准备失败、API 错误、模型失败、评分失败、超时和缺失记录均保留。没有原始评分时标记未知，分母保持计划值，不能丢弃后宣传完整通过率。已取得一次完整成功的题可确认其 pass@3；其余存在未知尝试的题给出未知数量和成功率区间。不得因结果不理想自动重跑或换题。

效率统计列出可观测分母。累计 Agent 执行耗时采用全部顶层 `result.duration_ms`，包含模型调用、工具执行与续行，不包含镜像准备及 Agent 退出后的评分。Token 和费用按实际遥测覆盖范围报告；CLI 估算不是供应商账单，缺失的 Goal 评估器或子 Agent 开销不记为零。

报告依据实际结果撰写，不预设 Native 获胜。16 题的结果不能证明其他任务上的质量相同，也不能将完整执行方式之间的差异全部归因于某一项 Comet 特性。
