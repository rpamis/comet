# Comet Dashboard 工作台重构设计

## 目标

将 `comet dashboard` 重构为基于 Ant Design 与 React 的只读工作台。界面保持现有
深色蓝绿主题及亮色模式的语义色，不沿用 Ant Design 的默认色彩；提升布局一致性、
项目切换可靠性与窄屏可用性。

用户可在 Header 中从 Comet 已初始化项目的统一列表中切换项目，切换后在同一页面加载
对应快照。Dashboard 不增加初始化、执行、归档或其他会修改项目状态的功能。

## 范围

### 包含

- 采用 Ant Design 组件重构 Dashboard 核心界面，并在现有 React/Vite 前端中保留业务逻辑边界。
- 通过 `~/.comet/installations.json` 的项目注册表发现 `comet init` 等流程已登记的项目。
- 服务端提供受注册表约束的项目列表与指定项目 Dashboard 快照。
- 使用 Header 项目选择器无刷新切换项目，保留侧边栏。
- 重做 Header，采用“上下文枢纽”布局。
- 统一卡片、标签、按钮、抽屉、空状态、告警与响应式栅格的尺寸和间距。
- 在 Change 详情标题旁增加 Change 名称复制按钮。

### 不包含

- 在 Dashboard 内执行任何会写入项目的 Comet 命令。
- 改变 Classic、Native 的采集数据契约和工作流状态机。
- 接受前端任意路径并读取其文件系统内容。
- 迁移或修改项目注册表的既有写入语义。

## 架构

### 服务端

新增 Dashboard 项目目录模块，复用 `platform/install/project-registry.ts` 的读取与校验能力。
目录模块将注册表条目映射为仅供 Dashboard 使用的稳定项目 ID、显示名称、路径、最后活动时间
和可用性状态。

项目可用性分为：

- `available`：路径存在且可读取；
- `missing`：登记路径已不存在；
- `unreadable`：路径存在但无法读取。

现有 Dashboard 服务新增两类只读 API：

- 项目列表 API：返回当前命令行目标项目与注册表项目的去重列表，按 `lastSeenAt` 倒序。
- 项目快照 API：只接收项目 ID；服务端在目录中解析 ID 后调用现有采集器。未知 ID 返回明确的
  客户端错误，不将输入解释为路径。

Dashboard 启动时传入的项目始终被放入目录，因此注册表为空、损坏或尚未记录当前项目时，用户
仍能查看当前项目。注册表以非严格模式读取：损坏的注册表不会阻止现有 Dashboard 启动，而是
使项目列表退化为当前项目并给出可诊断状态。

### 前端

前端继续使用 React 与 Vite，增加 Ant Design 及其图标包。业务采集、产物解析与 Markdown
预览保持在现有独立模块中；页面组件只消费项目目录和快照 API。

核心组件边界：

- `DashboardShell`：主题、侧边栏、Header、当前项目与请求生命周期。
- `ProjectSelector`：Ant Design `Select` 的搜索、可用性标签和项目选中行为。
- `WorkbenchHeader`：项目上下文、工作流切换、全局搜索、刷新与主题操作。
- `ClassicWorkspace` 与 `NativeWorkflowPanel`：保留现有流程展示和领域数据形状。
- `ChangeDetailHeader`：展示 Change 名称、状态与复制名称按钮。
- `ArtifactDrawer`：以 Ant Design Drawer 承载现有产物预览管线。

## 界面设计

### Header：上下文枢纽

Header 为一行稳定工具栏，不再显示“项目仪表盘”标题加路径的双行信息，Classic/Native 也不再
作为孤立、放大的切换控件。

从左至右：

1. 移动端侧边栏按钮与 Comet 品牌；
2. 项目选择器：项目图标、项目名、截断路径和下拉箭头组成一个完整控制；
3. 紧凑的 Classic/Native 分段切换，紧邻项目选择器，表达它属于当前项目上下文；
4. 居中或弹性占位的变更搜索；
5. 右侧的自动刷新说明、手动刷新与主题切换。

在窄屏下，项目选择器优先占据第一行并允许路径截断；工作流与操作区折行或收纳，按钮保持
一致的最小触控尺寸，不出现重叠、压缩变形或横向溢出。

### 工作台与侧边栏

侧边栏继续用于产品标识、只读工作台导航与状态说明；桌面端固定宽度，移动端通过 Drawer
显示。主内容维持“概览—变更工作区—详情”的信息层级，并用一致的响应式栅格让列表、详情和
建议区在不足宽度时依序堆叠。

Ant Design 的 `Layout`、`Menu`、`Select`、`Segmented`、`Input`、`Button`、`Card`、`Tabs`、
`Drawer`、`Alert`、`Empty`、`Spin`、`Tag`、`Tooltip` 和 `message` 组成界面基础。主题令牌会
映射现有的颜色变量、圆角、阴影和字号等级，使深色蓝绿主题保持不变。

### Change 名称复制

Change 详情的标题行中，名称之后、状态标签之前放置无文字的复制图标按钮。该按钮提供
`Tooltip`、可访问名称“复制 Change 名称”，复制成功后短暂显示成功图标并用轻量消息反馈；
失败时显示原因。文件路径旁现有复制操作继续存在，仍只用于复制路径。

## 数据与状态

- 项目切换使用 `AbortController` 取消前一个请求；只有仍与当前选择匹配的响应能够更新快照。
- 切换项目后清空变更选择和搜索条件，保留主题与工作流偏好。
- 自动刷新只请求当前项目；手动刷新同时刷新项目列表的可用性。
- 请求失败保留上一份成功快照，并以非阻塞 `Alert` 或消息提示错误，避免内容闪为空白。
- 最近一次有效项目选择可存入浏览器本地存储；每次加载均由服务端项目目录重新校验。
- 无可用登记项目时仍显示当前项目；对于失效项目，在选择器中展示不可用状态而非在选择时静默失败。

## 错误处理

- 注册表缺失：项目列表仅包含启动目标项目。
- 注册表内容无效：不影响目标项目 Dashboard，界面显示项目索引不可用的诊断。
- 登记路径缺失或不可读：保留在列表中并禁用选择，说明原因。
- 未知项目 ID：API 返回确定性客户端错误，不访问用户指定路径。
- 单个项目采集失败：保留当前可见快照，提示该项目加载失败；用户可刷新或选择其他项目。

## 验证

新增和更新的测试覆盖：

1. 项目目录：空、损坏、重复条目、排序、当前项目兜底、缺失路径、不可读路径和稳定 ID。
2. HTTP API：列表输出、只允许已登记 ID、未知 ID 被拒绝且不能触发任意路径读取。
3. 前端请求：快速切换时，过期响应不能覆盖当前项目；失败时保留最后成功内容。
4. 浏览器回归：项目选择、Header 响应式布局、Classic/Native 切换、Change 名称复制及其反馈、
   加载/空/错误状态。
5. 现有 Classic、Native、产物预览和移动端侧边栏行为的回归。

实现后执行受影响的 Dashboard Vitest 测试、Dashboard Playwright 测试、受影响源文件的格式检查
与 `pnpm build:dashboard`。由于涉及 Dashboard 服务 API 和前端布局，但不改变 Runtime 或发布资产，
不要求在本地默认运行全量仓库测试；CI 继续覆盖完整检查。

## 发布说明

这是用户可见的 Dashboard 能力升级。实施完成后，应先依据 `origin/master` 版本、当前
`package.json` 和最近发布 tag 确定下一个版本；如当前分支已有高于 master 的发布条目，则将最终
用户可感知的工作台升级合并到同一版本的英文 `CHANGELOG.md` 条目中，而不记录实现迭代过程。
