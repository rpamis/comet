# Dashboard 统一弹框交互设计

## 背景

Dashboard 当前存在多种内容弹框：项目知识详情、项目知识来源预览、产物文件预览、设置页以及创建和编辑表单。它们的关闭和全屏入口不一致：部分弹框同时显示全屏按钮和默认关闭 `×`，部分弹框只有默认关闭按钮，用户需要在不同弹框中理解不同的操作方式。

## 目标

1. 统一 Dashboard 内容弹框的右上角操作：移除独立关闭 `×`，在原位置只保留全屏/还原按钮。
2. 统一项目知识详情、来源文件预览、产物预览、设置和内容表单的全屏能力与视觉动效。
3. 保留遮罩点击、Escape 和表单操作按钮等关闭路径，避免移除 `×` 后无法退出弹框。
4. 让全屏状态下点击背景回到普通卡片，而不是直接关闭或丢失当前内容。
5. 继续使用 Ant Design Modal 的焦点、键盘和遮罩基础行为，避免重写确认类弹框。

## 非目标

- 不改变 `Modal.confirm` 等短暂确认提示的确认、取消和危险操作语义；这类弹框不承载长内容，不增加全屏入口。
- 不改变弹框内表单字段、保存逻辑、数据来源读取逻辑或 Markdown/JSON/YAML 渲染逻辑。
- 不增加浏览器原生 Fullscreen API；这里的“全屏”是 Dashboard 卡片在页面内占满可用视口。
- 不调整 Dashboard 其他非弹框页面的布局和导航。

## 交互方案

### 统一弹框容器

新增 Dashboard 内部可复用的内容弹框壳层，统一封装以下能力：

- Ant Design Modal 的打开、销毁、焦点和键盘行为；
- 自定义标题区和右上角全屏/还原按钮；
- 普通卡片与全屏状态的尺寸、定位、遮罩和过渡样式；
- 遮罩点击和 Escape 的状态转换；
- `全屏展示`、`退出全屏` 等无障碍名称和 Tooltip。

现有项目知识详情、项目知识来源预览、产物文件预览和设置弹框复用这一契约。新增项目知识、新增个人偏好、新增项目记忆和纠正记忆等内容表单也接入同一套标题操作和全屏样式。

产物文件预览当前为自定义覆盖层而非 Ant Design Modal，保留其内容读取、目录和文档滚动逻辑，仅将标题区操作和状态转换适配到统一容器的交互契约。

### 状态转换

| 当前状态 | 操作 | 结果 |
| --- | --- | --- |
| 普通卡片 | 点击右上角全屏按钮 | 卡片从中心向四周扩展为全屏 |
| 全屏卡片 | 点击右上角还原按钮 | 回到普通卡片 |
| 普通卡片 | 点击遮罩 | 关闭弹框 |
| 全屏卡片 | 点击遮罩 | 先还原为普通卡片，内容和表单状态保留 |
| 普通卡片 | 按 Escape | 关闭弹框 |
| 全屏卡片 | 按 Escape | 先还原为普通卡片 |
| 任意状态 | 点击完成、保存、取消等业务按钮 | 沿用原有业务逻辑 |

关闭弹框时清理原有全屏状态；重新打开时从普通卡片开始。全屏切换不应重置异步加载内容、滚动位置、目录选择或表单草稿。

### 视觉和动效

- 普通状态仍使用现有 Dashboard 设置页风格的圆角卡片、边框和遮罩。
- 全屏切换使用统一的中心扩散过渡，卡片的尺寸、位置、圆角和遮罩同步变化，避免直接闪变到视口尺寸。
- 项目知识详情、数据来源预览、产物预览和设置弹框使用同一时长、缓动曲线和 reduced-motion 降级规则。
- 全屏时正文区域继续独立滚动；来源预览已有目录、代码和 Markdown/JSON/YAML 渲染不受影响。
- 右上角按钮保留足够点击区域，Tooltip 和 `aria-label` 根据状态显示“全屏展示”或“退出全屏”。

## 实现边界

### 组件

- 抽取或扩展 Dashboard 内容弹框壳层，避免在每个调用点重复维护 `fullscreen`、关闭和标题操作。
- 将设置弹框和项目知识预览弹框现有的全屏状态迁移到共享壳层。
- 将创建/编辑类内容 Modal 的默认关闭图标禁用，并接入统一标题区和全屏状态。
- 将产物预览覆盖层的关闭按钮替换为统一的全屏/还原按钮，并接入相同的遮罩状态转换。
- 确认类 `Modal.confirm` 保持独立，不强行接入内容弹框壳层。

### 样式

- 删除内容弹框默认 `×` 的可见入口，不通过全局隐藏影响确认类弹框。
- 集中定义标题操作区、普通/全屏容器状态、遮罩点击和过渡样式。
- 保持现有浅色/深色主题和移动端尺寸规则。

## 测试设计

### 浏览器测试

- 每类内容弹框均验证右上角不再显示关闭 `×`，并显示全屏按钮。
- 点击全屏后验证弹框进入全屏状态，按钮名称变为“退出全屏”，再点击可还原。
- 普通状态点击遮罩验证弹框关闭；全屏状态点击遮罩验证先还原且内容仍在。
- 验证 Escape 在全屏状态先还原，在普通状态关闭。
- 验证项目知识详情、来源 Markdown/JSON 预览、产物预览、设置和表单草稿在全屏切换前后保持。
- 验证 `Modal.confirm` 仍保持原有确认/取消行为。

### 源码和样式检查

- 运行受影响的 Dashboard 浏览器测试。
- 运行 Dashboard Web 源码契约测试和 ESLint/Prettier 检查。
- 涉及 Dashboard 编译产物时运行 `pnpm build:dashboard`。

## 验收标准

1. Dashboard 所有内容弹框的右上角原关闭按钮位置都显示全屏/还原按钮，不再单独显示 `×`。
2. 普通状态点击背景关闭，全屏状态点击背景还原为普通卡片，且不会丢失正文、滚动位置或表单草稿。
3. 所有内容弹框的全屏切换均采用一致的中心扩散动效，并在 reduced-motion 环境下平稳降级。
4. 项目知识、数据来源、产物文件的内容渲染和原有业务操作不回归。
5. 确认类弹框的确认/取消行为不受影响。
