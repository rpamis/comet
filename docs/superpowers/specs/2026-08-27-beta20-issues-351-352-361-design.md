# Beta20 Issues 351, 352, and 361 Design

## Goal

修复 beta20 中 Native Portable v4 大状态读取失败、CodeGraph 状态层级混淆，以及 Qwen Code/Trae 无法由 `/comet` 调度 Classic 子 Skill 的问题。

## Scope and approach

### Issue #351

只移除 Native change state reader 对完整 `comet-state.yaml` 设置的任意 256 KiB 总大小限制。继续使用现有的路径 containment、普通文件、UTF-8、文件身份和读取一致性检查；其他 Native artifact reader 的合理大小限制不变。回归测试使用可解析的超大 Portable v4 状态，并覆盖真实的 Native change 读取/扫描路径。

### Issue #352

在现有 CodeGraph project-index 诊断上增加分层集成诊断，同时保留现有 `status`、`repairable`、`remediation`、`detail` 字段以兼容已有消费者。

诊断分为：

- `cliStatus`：CLI 是否可解析；
- `indexStatus`：项目索引是否未初始化、不完整、过期、就绪或不可用；
- `mcpStatus`：CodeGraph 官方支持 Agent 的 MCP 注册是否未发现、未注册、部分注册、全部注册或检查不可用；
- `agents`：每个发现的支持 Agent 的配置路径、注册状态、配置范围和可用性；
- `effectiveForAgent`：以 Agent 为键的配置就绪推断，只有 CLI、项目索引和该 Agent 的有效 MCP entry 都满足时为 `true`。

“有效”表示 Comet 能从本地配置确认 Agent 已具备调用条件，不声称已对 Agent 发起真实 MCP tool call。配置检查覆盖 CodeGraph 官方安装器支持的 Claude Code、Cursor、Codex CLI、OpenCode、Hermes、Gemini CLI、Antigravity 和 Kiro；不存在的 Agent 不制造误报。Codex TOML、OpenCode JSONC、Hermes YAML 及其他 JSON 配置分别按其官方配置形状读取。

`comet doctor` 的文本输出分别显示 CLI、项目索引、MCP 注册和 Agent 可用性；JSON 输出提供稳定分层字段。`doctor --repair` 只修复项目索引，不隐式修改 Agent MCP 配置。`comet init` 在执行 CodeGraph 操作前后明确说明 CLI、MCP 注册目标/范围和项目索引；`--codegraph init` 只初始化项目索引，`--codegraph skip` 不调用 CodeGraph。

### Issue #361

同步中英文用户可见 Classic phase/preset Skills（`comet-open`、`comet-design`、`comet-build`、`comet-verify`、`comet-archive`、`comet-hotfix`、`comet-tweak`）：移除会阻止宿主模型调度的 `disable-model-invocation`，并将 OpenAI metadata 的 `allow_implicit_invocation` 设为 `true`。入口 Skill `comet`、Native/Classic workflow entry 保持可调用；独立只读 `/comet-review` 与内部 `/comet-any` 保持显式调用，不改变其非 `/comet` 主流程语义。

## Verification

- Native change tests prove an oversized valid state is readable and safety checks remain covered.
- CodeGraph integration tests prove each supported config shape and the layered status model; Doctor and init tests prove human/JSON output and optional behavior.
- Bilingual Skill metadata contract tests prove the intended implicit-invocation policy.
- Rebuild generated Native/Entry assets when source changes require it, then run focused tests, formatting, lint/build checks, and the final full CI-equivalent suite before delivery.
- Version `package.json` and the generated manifest to `0.4.0-beta.20`; add only user-visible beta20 behavior to the English changelog.
