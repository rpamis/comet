# 手动新增项目知识设计

## 背景

项目知识当前主要由项目来源和工作流事件自动生成。项目中仍可能存在尚未写入规范文件、但需要提供给 Agent 的稳定事实或协作约定。Dashboard 需要支持用户补充这类知识，同时保持项目知识与个人记忆的边界。

## 目标

- 允许用户在当前项目中创建一条结构化项目知识记录。
- 将手动记录标记为用户提供，保留现有自动学习、查询、纠正和忘记流程。
- 防止手动项目知识被自动学习内容覆盖。
- 在 Dashboard 中明确提示记录的来源和验证状态。

## 非目标

- 不把个人偏好迁移到项目知识。
- 不新增一套独立的项目规则执行器；确定性规则仍应进入项目配置、Native/Classic spec、测试或 CI。
- 不开放任意 Provider 数据库编辑，也不支持批量导入。

## 用户流程

1. 用户打开 Dashboard 的“项目知识”页面，点击“新增项目知识”。
2. 填写类型、标题和摘要；可选填写适用路径、适用操作、来源和验证命令。
3. 保存后，插件创建 `authority: user`、`state: active` 的记录，并刷新 Dashboard 快照。
4. 记录列表展示“用户提供”标签；没有来源或验证命令时展示“未验证”提示。
5. Agent 检索时与其他 active 记录一样使用该记录；用户仍可纠正或忘记它。

## 数据与接口

- 在 Project Knowledge Plugin 增加 `create` capability。
- `create` 只接收结构化字段，不接收任意完整记录，服务端负责生成稳定 ID、项目 ID、时间戳和默认空列表。
- `type` 使用已有记录类型；`applicablePaths`、`operations`、`verification` 使用已有记录字段和校验规则。
- 手动记录的 `authority` 固定为 `user`，`state` 固定为 `active`。
- 如果提供来源，保存为结论来源；如果未提供来源，记录仍可保存，但 Dashboard 明确显示未验证。
- 复用 Provider 的 `upsert`，不改变 Local/Remote Provider 契约。
- 现有 `mergeProjectKnowledgeRecord` 继续以用户记录优先，自动记录不得覆盖其摘要和结论。

## Dashboard

- 在项目知识记录区域增加“新增项目知识”按钮。
- 表单采用现有 Ant Design 组件和页面样式。
- 类型使用已有六类记录类型的中文标签。
- 路径、操作、来源、验证命令使用按行输入，空行忽略。
- 保存失败显示插件错误；成功后关闭表单并刷新数据。

## 验证

- 插件测试：`create` 生成用户记录、缺少必填字段时报错、手动记录可被查询。
- Provider 测试：手动记录不会被自动记录覆盖。
- Dashboard 源码测试：新增入口、表单字段和 create 调用存在。
- Dashboard 浏览器测试：可打开表单、填写并保存手动项目知识，列表显示用户提供标签。
