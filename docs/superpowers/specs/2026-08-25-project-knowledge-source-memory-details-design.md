# 项目知识来源与最近记忆详情设计

## 背景

Dashboard 的“项目知识”页面目前在“数据来源”中主要展示来源路径、关联记录数、收录状态和更新时间。来源列表没有搜索入口，也不能打开来源文件原文；当来源较多时，用户只能从当前可视区域感知到部分内容。

“最近一次任务使用的记忆”目前展示了摘要、使用原因和提供方式，但顶部概览项与下方记忆详情之间的跳转不够明确，用户不能稳定地从最近使用记录进入完整详情。

## 目标

1. 让用户可以搜索全部项目知识来源。
2. 让用户点击来源后在 Dashboard 内查看项目内文件的完整原文和基本元数据。
3. 让用户从“最近一次任务使用的记忆”概览直接打开对应记忆的完整详情。
4. 保留现有项目知识记录详情、个人记忆管理和未提交用户改动，不扩大到新的知识编辑能力。

## 非目标

- 不改变项目知识的索引、召回、排序或学习逻辑。
- 不把来源文件复制到项目或 Dashboard 专用目录。
- 不为远程 Provider 设计新的远程文件下载协议；远程来源若无法在当前项目中读取，显示明确的不可读取状态。
- 不改变个人记忆的存储、作用域、生命周期或应用判定。

## 方案选择

### 方案 A：只增加前端搜索和关联记录详情

可以快速复用当前快照，但无法查看来源文件原文，不满足需求，放弃。

### 方案 B：增加安全的来源读取能力并在 Dashboard 中查看

项目知识插件增加一个只读的 `read-source` 能力。Dashboard 传入项目相对路径，由插件在项目根目录内完成路径校验和文本读取；前端在来源页增加搜索和可点击来源，并使用 Ant Design 抽屉展示文件内容。该方案满足完整查看需求，同时把文件访问安全边界留在 Runtime/插件层，作为采用方案。

### 方案 C：复用现有检索或上下文展开能力

现有检索返回的是匹配片段，现有上下文展开主要面向知识记录，不保证返回完整源文件，交互和语义都不适合来源浏览，放弃。

## 详细设计

### 1. 来源数据与读取接口

项目知识 Dashboard 快照继续提供来源索引元数据。前端来源集合由以下两部分合并去重得到：

- 本地索引报告的全部来源；
- 项目知识记录中声明的来源，即使该来源当前没有可用索引记录，也保留在列表中。

项目知识插件增加 `read-source` 能力：

```text
输入：{ source: string }
输出：
  {
    kind: 'source',
    source: string,
    content: string,
    size: number,
    modifiedAt?: string,
    truncated: boolean
  }
```

读取规则：

- 只接受非空项目相对路径，并统一路径分隔符；
- 拒绝绝对路径、路径穿越、项目根目录之外的路径和目录；
- 使用现有项目文件安全读取约束，仅读取 UTF-8 文本；
- 对单个文件设置合理的读取上限，超过上限时返回已截断标志和可识别状态，不把截断内容伪装成完整文件；
- 文件不存在、不可读、是二进制或超出限制时返回结构化错误，由 Dashboard 显示可理解的原因；
- 不返回访问令牌、绝对本机路径或其他不必要的运行时信息。

### 2. 数据来源页面

“数据来源”页面保留现有表格视觉语言，并增加：

- 来源搜索框，按来源路径、来源类型、收录状态和关联知识标题过滤；
- 来源总数与当前匹配数量；
- 全部来源列表，不对数据做固定数量截断；
- 来源行的可点击/键盘操作状态，以及选中样式。

点击来源后调用 `read-source`，打开来源详情抽屉。抽屉包含：

- 文件路径、文件类型、收录状态、更新时间和文件大小；
- 关联的项目知识记录列表，点击记录可回到现有项目知识详情；
- 使用等宽字体、可滚动的原文区域，原文按纯文本展示，不解释或执行 Markdown/HTML；
- 加载中、读取失败、来源不存在和内容截断状态。

搜索只影响来源列表，不改变后端索引和 Provider 查询；打开抽屉后，当前搜索条件和选中来源保持不变。

### 3. 最近一次使用的记忆

顶部概览中的每条记忆改为明确的可交互项：

- 支持鼠标点击、Enter 和 Space；
- 提供“查看记忆详情”的可访问名称；
- 选中后同步更新个人记忆列表的选中记录和右侧“记忆应用详情”；
- 详情区域继续展示完整记忆文本、匹配上下文、最近应用、应用历史、作用范围、状态和证据来源；
- 若当前概览项没有对应的管理记录，则不伪造详情，显示“该记忆详情暂不可用”及原因。

顶部概览仍只展示最近一次任务实际提供给 Agent 的记忆，不改为展示全部已保存记忆。

### 4. 错误处理

- 来源读取失败不影响来源列表和其他来源继续使用；
- 插件返回的结构化读取错误在抽屉内展示，不弹出无法定位的通用错误；
- 搜索无结果时显示当前搜索条件下没有匹配来源；
- 记忆详情缺失时保留概览信息，并明确提示详情不可用；
- 远程 Provider 关联的来源若不在当前项目中，显示“当前项目无法读取该来源”，而不是空白内容。

## 测试设计

### 项目知识插件

- 能读取项目内的文本来源并返回原文、大小和更新时间；
- 拒绝绝对路径、路径穿越、项目外路径和目录；
- 对不存在、不可读或超大来源返回结构化失败/截断结果；
- 不改变现有项目知识列表、检索和 Provider 契约。

### Dashboard Web

- 来源页面展示全部来源并显示数量；
- 来源搜索按路径和关联记录过滤；
- 点击来源后显示文件原文和元数据；
- 读取失败和无结果状态可见；
- 最近一次记忆概览可通过按钮和键盘操作打开对应的完整详情；
- 现有项目知识记录筛选、个人记忆管理和删除行为继续通过回归测试。

## 验收标准

1. 用户进入“项目知识 → 数据来源”后，可以看到来源总数并搜索任意来源路径。
2. 用户点击来源后，可以在 Dashboard 抽屉中阅读该项目内文件的完整原文，而不是只能看到路径或检索片段。
3. 对不安全路径或不可读取来源，页面显示明确原因且不会泄露项目外文件内容。
4. 用户点击“最近一次任务使用的记忆”中的任意项目后，可以看到对应记忆的完整详情和应用历史。
5. 以上交互有自动化回归测试覆盖，且不破坏当前工作区已有的未提交改动。

## 变更补充：项目知识顶部概览的单条展开

本次反馈确认，项目知识页面顶部不应继续使用“最近一次使用的记忆”作为展示名称，也不能依赖页面下方的个人记忆详情面板来完成查看。该区域改为项目知识语境下的独立展开概览：

- 区域标题使用“最近一次任务使用的项目知识”，说明文字明确这是本次任务实际提供给 Agent 的项目知识；
- 收起项显示项目知识标题、项目知识类型、可读的短预览和“展开详情”操作，不使用横向单行省略来承载主要信息；
- 点击或键盘操作只在当前卡片下方展开一条项目知识详情，另一条展开时自动收起；
- 展开内容使用“项目知识内容”“为什么使用”“提供给 Agent 的内容”“应用结果”“最近应用”等用户可理解的标签，并显示完整文本；
- 项目知识概览的展开详情直接使用已有 `manifestPreview` 数据，不新增后端接口；
- 个人记忆页面继续使用原有“最近一次任务使用的记忆”文案和个人记忆语义，两个页面不得混用名称。

新增验收标准：

6. 用户在“项目知识”页面看到的是“项目知识”而不是“个人记忆”，且点击任意单条概览后能在当前区域直接阅读完整内容。
7. 展开详情必须显示项目知识类型和应用上下文；切换另一条后前一条收起，键盘操作与鼠标操作结果一致。

## 变更补充：数据来源列表布局与完整浏览

数据来源列表的表头和数据行必须使用同一组 Grid 列定义，数据行作为可点击按钮时仍然占满来源区域宽度，不能根据按钮内容收缩。来源主体在固定高度的项目知识工作区内独立滚动，表头留在滚动区域上方；不做前端分页，也不截断 `sourceEntries`，因此总数为 124 时用户可以通过滚动访问全部 124 条来源。

搜索只改变滚动主体中的可见行，并保留总来源数和匹配数。响应式布局继续沿用现有断点，在窄屏隐藏次要列，但来源路径和关联记录列仍保持同一列轨道。回归测试必须验证：来源按钮数量等于 fixture 的全部来源数、来源主体可滚动、最后一条来源可通过滚动访问，并且表头列与首行列的起始位置一致。
