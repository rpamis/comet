# 测试

<!-- comet-development-rule:tests -->

- 测试目录跟随被测对象：`test/app/`、`test/domains/<domain>/`、`test/platform/`、`test/scripts/` 或 `test/repository/`。
- `test/fixtures/` 中的发布快照和兼容样本默认冻结；需要更新时先证明外部契约确实改变。
- 文件系统、安装、Hook 和用户配置测试必须使用临时目录，不读取或修改真实 HOME。
- 回归测试验证可观察行为或曾经复现的失败，不复制实现细节。
- 先按行为和依赖关系运行受影响的测试文件或测试名，再补相邻契约检查；全量测试条件遵循根 `AGENTS.md` 的“测试”章节，不因跨模块、Runtime、安装或交付标签自动扩大范围。
- 仅修改多个测试文件、生成测试资产或扩大单个测试文件的覆盖范围，不自动触发仓库全量测试；先运行对应文件或测试名。
- Native 的完整独立验收覆盖当前候选的全部验收项，不等于 `pnpm test`；优先复用仍与候选和执行上下文匹配的 Runtime 检查。
- 全量测试同一时刻只允许有一轮；等待工具超时、单个测试耗时较长或尚未出现汇总时，不并行重启全量测试。先记录首个失败/超时，定位原因后再决定是否重跑。

## 用户问题回归

- 修复用户问题时遵循根 `AGENTS.md` 的完成标准和 `docs/architecture/badcase-maintenance.zh.md`。先拆分独立失败行为，再为每个行为登记来源、稳定 case ID、精确可执行测试和预期/禁止结果。
- 新增测试与复用测试均可；复用时逐项证明现有断言覆盖原报告，不以测试文件存在或整个 suite 通过代替行为覆盖。旧代码失败/新代码通过应使用相同输入和断言，记录无法复现或未执行的部分。
- CLI、命令 bundle、打包安装、恢复、迁移和状态机问题应测试相应公开入口与可观察状态；内部 mock/单元测试只证明其自身边界。UI 问题另做浏览器验证；模型遵循问题另做真实模型 Eval。
- 对权限、审批、候选与证据绑定、跨 workflow 隔离、恢复副作用等风险补充相关禁止行为断言，并验证合法路径仍可完成。坏输入“没有报错”或命令退出码为零都不足以证明状态正确。
- 保留历史 badcase 的来源与行为覆盖。迁移、替换、退休或降低断言必须说明理由及覆盖去向，提交等价证据并经 Review；不得静默删除、skip、改名逃避登记校验。
