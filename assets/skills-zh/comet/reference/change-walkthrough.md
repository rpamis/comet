# 按需生成变更说明

项目 `.comet/config.yaml` 的 `change_walkthrough` 默认及缺省为 `true`，按本文件生成变更说明；开启会增加讲解内容的 token 消耗。仅显式 `false` 时跳过额外讲解整理、详细指引读取和 HTML 渲染，保留原有完成摘要，不为讲解额外读取差异或请求模型。

## Build 收尾

复用当前上下文、本次实际差异及已有检查结果，按功能组织简短讲解。不要启动额外 Agent、模型服务或检查。小改动一组即可；大改动先放主要变化，其余由模板折叠。Native Supervisor 只讲已集成结果，未集成子任务明确列为未完成。

先用用户能理解的话概括结果，再说明“原来怎样 → 现在怎样”和原因。每组列相关文件、增改删或重命名标签及足以核对的关键代码或局部 diff；路径可附行号或符号。删除解释移除的行为，重命名不虚构功能变化。复用已知比较范围，不确定或混有用户无关修改时说明限制，不把无关工作归为本次成果。不复制密钥、凭据或无关内容，不用整份 diff 填满页面。

将以下内容写到项目工作区以外的系统临时 JSON 文件，避免讲解输入影响实现检查。它只是渲染命令的输入，不是新的 workflow 状态或必需交接协议。模型只填内容，不编写 HTML、CSS 或脚本：

```json
{
  "summary": "搜索支持按标签筛选",
  "scope": "已知比较范围与限制，例如 HEAD 与本次工作区差异",
  "changes": [
    {
      "title": "标签筛选",
      "before": "只能输入关键词",
      "after": "关键词与标签可以一起筛选",
      "reason": "缩小结果范围",
      "files": [{ "path": "src/search.ts:12", "kind": "modified", "code": "关键代码或局部 diff" }]
    }
  ],
  "verification": [
    { "label": "Builder 自检", "status": "passed", "detail": "实际命令、结果与覆盖范围" },
    { "label": "独立验收", "status": "not-run", "detail": "尚未执行" }
  ]
}
```

`kind` 为 `added`、`modified`、`deleted` 或 `renamed`。验证状态只用 `passed`、`failed`、`not-run`、`unknown`；分别列 Builder 自检、Runtime 检查、独立验收和未执行项，包含实际结果、已知风险与限制。讲解不能代替验证证据。

### 按需画关系图

实际变化涉及执行顺序、调用关系或数据去向时，优先用一张短流程图讲清主路径及关键分支；模块拆分、替换或职责转移时，用前后框线对照。图放在总览之后，按理解顺序关联文件和代码。简单文案、配置值或单点修改可以不画图，不为凑图虚构流程或关联。一般一到两张即可，图不替代说明与验证。

在同一临时内容中可选填写 `diagrams` 数组。模型只提供节点、连线和标签，固定模板绘制内嵌 SVG；不编写 SVG、HTML、CSS、Mermaid 或脚本，也不增加 Agent 或模型调用。例如为上面的搜索修改添加流程图：

```json
{
  "diagrams": [
    {
      "type": "flow",
      "title": "搜索路径",
      "nodes": [
        { "id": "input", "label": "关键词与标签" },
        { "id": "filter", "label": "组合筛选", "file": "src/search.ts:12", "kind": "modified" },
        { "id": "result", "label": "匹配结果" }
      ],
      "edges": [
        { "from": "input", "to": "filter" },
        { "from": "filter", "to": "result" }
      ]
    }
  ]
}
```

前后对照使用 `{"type":"comparison","title":"职责变化","before":{"nodes":[...],"edges":[...]},"after":{"nodes":[...],"edges":[...]}}`，两侧各提供同样的节点和连线结构。节点可选 `kind` 沿用文件的增改删／重命名标签；只有真实变化才标记。节点的可选 `file` 必须与本次 `changes[].files[].path` 完全一致，点击后定位到对应代码详情；同一路径存在多个片段时，在两处使用相同的行号或符号限定。

短图每侧为 2–6 个节点、1–8 条连线，每层最多两个节点。节点 ID 唯一，按执行或依赖顺序排列，`from`／`to` 指向已有节点且从前向后连线；连线可选 `label` 简短说明条件。复杂循环或过大的关系拆成小图，只展示有依据的主路径，并在正文说明省略的分支。无须画图时省略 `diagrams`；不把页面图误称为真实运行证据。

运行 `comet walkthrough <native|classic> <change-name> --project-root <project-root> --file <temporary-json>`。成功返回绝对 `path`，固定模板写入当前 change 目录的 `walkthrough.html`。聊天保留简短摘要并提供 `[查看变更说明](<绝对路径>)`，在既有接受或交付决定前展示。页面可直接在浏览器打开。失败时说明“变更说明未生成”及原因，修正后可重试；原有工作流继续，不新增阶段或审批。

临时输入完成后可清除，避免混入实现差异；不能删除用户文件。不要把讲解页加入 brief 正式产物、检查输入、候选或额外绑定。

## Verify 更新同一页面

沿用实际检查及独立验收结果。仅补验证时，临时 JSON 只写 `verification` 数组，运行同一命令并加 `--verification-only`；渲染器复用页面中保存的讲解和图，无需模型再次整理。代码变了就同步受影响讲解、节点和连线，提交完整内容替换同一页面，并如实更新结果。缺页时可从当前上下文生成，不能把缺页作为验收阻塞。独立 Verifier 先独立核查需求和代码，再把 Builder 讲解作为线索。

更新页面不运行代码检查、不改变 Run 或批准。完成回复提供当前页面链接。关闭开关时不更新或补生成；无需删除已有页面。

## Archive 保存

随现有 change 材料保存已有页面，使用 Runtime 返回的归档目录提供最终本地链接。归档时不补生成、不重新整理讲解、不因缺页阻塞。仅在文件确实存在时提供链接；没有页面时保留原有完成摘要。
