# 宿主能力核对

新任务开始、切换宿主或执行配置改变时，在批准 Shape/Open 或开始依赖该配置的实现前核对本节。沿用当前宿主中已经确认且仍可用的能力，不为每个阶段重复探测。

Agent 根据当前平台实际提供的工具、Skill 清单和项目规则核对能力。CLI 不能枚举宿主工具；命令安装成功不代表可以派发审查者，也不代表外部 Skill 已获准使用。

- Native 必须能建立与 Builder 分开的 Verifier 会话，并跟踪原任务。Classic 的 `review_mode: standard|thorough` 需要独立 reviewer；选择子代理实施方式时还需要可跟踪的 implementer。只读限制针对项目实现与需求文件，审查者仍须能调用公开 Runtime 命令领取自己的 Action、请求检查和提交结果；不能把整个会话设为禁止 Runtime 写入的沙箱。
- Classic 新建与规格验证需要当前阶段指定的 OpenSpec Skill 和 CLI。full Design 需要 brainstorming；选定规划、实施、TDD 或审查策略后，再核对该策略指定的 Skill。Native 不增加外部 Skill 依赖。只核对实际采用的策略，不把未选策略的依赖当成当前阻塞。
- Skill 必须既可加载，又符合当前用户授权和项目规则。安装缺失、明确禁用、会话无法独立或无法回报 Runtime 时，说明具体缺口和恢复条件，在受影响的实现开始前处理。用户已有选择覆盖所需能力时直接继续，不追加确认。

能力不明时先核对可用工具说明，不为探测而派发真实实施或验收任务。保留用户可以选择的工作方式；缺口明确时说明需要安装、授权或更换宿主，不能悄悄关闭独立审查、改用另一种执行策略或把未知标为通过。用户后来明确改变策略时，按原 Runtime 决策路径更新。
