# 编辑后继续原流程

Build、Verify 或待归档阶段发生编辑时，由当前 Agent 判断实际影响。文件内容变化不自动撤回批准、作废检查或重置阶段；不提交文件指纹、hash 或逐文件保留证明。

1. 读取实际改动、当前需求、相关调用和已有检查结果。可使用 Git 差异和当前文件；缺少必要上下文时补读原文，不以文件大小、扩展名或摘要替代判断。连续保存合并处理，不逐次增加审查或确认。
2. 根据实际影响继续工作：说明、注释或排版未改变行为和验收含义时，保留原 Run、阶段、批准、报告和检查；实际实现变化时，沿当前流程修订实现并验收；目标、验收标准、方案或授权范围变化且原决定未覆盖时，只请求受影响的决定。
3. Agent 使用平台工具执行必要检查并读取实际结果。原检查仍适用时保留其真实来源；需要补查时只执行所需命令。不要求 observe、prepare-applied、record、retainedChecks 或内容证明链。按当前 Action 模板向 CLI 提交实际检查报告，普通编辑不增加独立审查会话。
4. 新失败、中断、超时、结果未知和未执行均如实保留。修复后用实际新结果更新结论，不能用旧成功覆盖最新失败，也不能把历史检查描述成本轮执行。已经完成的单次操作不自动重放。
5. 已接受结果尚未归档时，Agent 确认当前改动仍符合原需求和验收结论，再继续原归档；需要修复或补查时按实际影响处理。归档中断沿原事务继续，Runtime 记录哪些写入和目录移动已完成，避免重复副作用。

用户确认、明确要求的独立验收、阶段权限、路径和工作区隔离继续生效。Runtime 维护步骤、执行者、命令、退出状态、日志路径、用户决定和归档进度；共享 SDK 的 Action 请求标识、安装包摘要和 Git 提交 ID 保留。

完成条件：Agent 已核对改动影响，必要检查有实际结果，当前结论与用户要求一致，原流程能够继续。没有新增信息时不为记账重开 Build 或 Verify。

## Agent 判断与 CLI 执行

Native 与 Classic 由当前 Agent 判断需求、文档和开发进展；CLI 执行明确选择的操作，保存原 Run、用户决定、真实结果和恢复进度。

- 文档是否完整、需求是否明确、是否需要目标 Spec，由 Agent 对照用户请求与项目要求判断。模板是写作参考，固定标题、措辞、语言比例和设计文档 frontmatter 不作为完成证明。机器需要的验收项、任务 ID、路径和结果字段按当前响应填写；存在未解决的用户决定时先处理该决定。
- 选择与任务匹配的现有 workflow/preset。Classic full 保留设计、实施计划和用户批准；外部工具真正要求的材料继续满足。已有 Run 和正式材料可供交接时直接使用，不为阶段切换重复抄写相同内容。需要独立材料供人阅读或外部工具使用时再生成。
- Agent 明确选择检查命令、工作目录及本次范围，使用平台工具执行并读取真实退出状态，再向 CLI 提交报告。状态查询和 Guard 只读取结果，不自行猜测并启动 Build。原命令仍在运行或结果未知时，先核对同一执行。
- 每轮失败后结合实际修改与结果决定继续修复、换方案或请求帮助。验收项 ID 集合未缩小不等于没有进展。使用现有说明表达判断，无需评分或进展证明；用户预算和实际执行上限仍生效。
- 优先使用当前 workflow 的业务入口和返回模板。CLI 装配 SDK 的 Action、领取和并发控制参数，并连续处理已经授权的内部步骤；用户决定、不同执行者、真实失败或外部等待仍返回当前实际下一步。恢复沿用原 Run 和原执行。
- Agent 判断是否值得并行及如何拆分任务。Runtime 维护实际依赖、工作区、任务状态和 Git 操作；父级验收覆盖全部已确认验收项，复用适用的子任务结果并补足缺口。用户选定的协作方式和独立验收要求继续保留。

完成条件：需要的用户决定已有明确记录，当前任务的实际结果可核对，验收覆盖已确认要求，归档与交付按原授权和真实进度完成。缺少检查、执行失败、超时或未知结果时如实说明，不能写成通过。
